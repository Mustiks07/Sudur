# content_build

Сборка базы содержания из лицензированных источников.

- **Владелец:** Opus
- **Задача:** [P03](../../docs/tasks/P03-content-build.md)
- **ТЗ:** 4.8, 4.9, 6.1, 8.10, 12.2, 12.3, ПР-02, ПР-04

Правила: [`AGENTS.md`](../../AGENTS.md). Публичный интерфейс — только `lib/content_build.dart`; внутренности — в `lib/src/`.

## Одна команда

Из корня репозитория:

```bash
dart run tools/content_build/bin/content_build.dart
```

Что происходит:

1. Скачивание в `third_party_cache/` (папка в `.gitignore`; повторно не качается, `--refresh` — скачать заново):
   - текст Uthmani из Tanzil в XML (`tanzil/quran-uthmani.xml`);
   - разметка страниц KFGQPC V2 и коды знаков QPC V2 для каждой страницы сборки (`layout/…/page582.json`);
   - сведения о сурах (`chapters/…`);
   - шрифты страниц QPC V2 (`fonts/…/p582.ttf`).
2. Проверки ПР-04 (если хоть одна не прошла — сборка останавливается).
3. Результат в `build/content/<id>/` (тоже вне git):
   - `content.sqlite` — база содержания по схеме ТЗ 12.2 (ADR 0004): **текст всего Корана** в `surah`, `ayah`, `word` и **разметка только страниц из конфигурации** в `word_layout`, `ayah_layout`, `page`, `line` (с `layout_id`);
   - `text.json` — текст всего Корана в формате тестовых данных (ADR 0004);
   - `derived.json` — отрывки по умолчанию и пары похожих мест (см. «Производные данные»);
   - `content.json` — страницы сборки вместе с разметкой (вид прототипа);
   - `fonts/`, `ATTRIBUTION.md`.

Параметры сборки — в [`config/prototype.json`](config/prototype.json): страницы (582–583), адреса источников, лицензии, ожидаемые числа и закреплённая контрольная сумма канона.

Флаги: `--fixture-out <путь>` — копия страниц (так собирается `packages/testing/fixtures/content_p582_583.json`), `--text-fixture-out <путь>` — копия текста всего Корана (`packages/testing/fixtures/quran_text.json`), `--no-fonts`, `--refresh`, `--verbose`.

## Производные данные (D01)

Отрывки по умолчанию и пары похожих мест **вычисляются из текста Tanzil**: сам текст не меняется, пары из QUL не берутся (права не подтверждены, ТЗ 6.1). Параметры — [`config/derived.json`](config/derived.json); все четыре (`halfPageWords` = 64, `minPhraseWords` = 5, `minAyahWords` = 2, `wordSimilarity` = 0,8) согласованы владельцем 19.11.2026. Пишутся в `passage_default` и `similar_pair` базы содержания и в `derived.json`; тестовая копия — `packages/testing/fixtures/derived.json`.

Без сети, из тестовых данных (так собран тестовый файл; печатает отчёт):

```bash
dart run tools/content_build/bin/derive.dart --out packages/testing/fixtures/derived.json
```

### Отрывки по умолчанию (`passage_default`, ТЗ 4.8, 12.2)

- 1–`passageMaxAyahs` (5, ТЗ 12.4) аятов; отрывок не переходит через границу суры, начинается и кончается на границе аята.
- **Без разметки страниц:** не больше `halfPageWords` слов; аят длиннее — отдельный отрывок («длинный аят»). `halfPageWords` = 64 — половина страницы мединского мусхафа в словах в среднем: 77 433 слова / 604 страницы / 2 ≈ 64. Согласовано владельцем 19.11.2026.
- **Где есть разметка** (сейчас страницы 582–583): отрывок на одной странице и не больше `pageFraction` (½) строк страницы (≤ 7 из 15); аят через две страницы или длиннее — отдельный отрывок (ADR 0004: правила страниц — только в области с разметкой). Аяты с разметкой и без неё в один отрывок не попадают.
- Цепочка аятов, которые могут стоять вместе, делится на наименьшее число отрывков, по возможности поровну (7 аятов — 4 + 3, а не 5 + 2).

### Похожие места (`similar_pair`, ТЗ 12.2, УП-05)

По ключам слов `quran_text` со встроенным нормализатором (ТЗ 10.1) — производные данные не зависят от модели:

1. **Повторяющиеся аяты:** аяты с одинаковыми ключами всех слов, от `minAyahWords` (2) слов — каждый с каждым (рефрены сур 55 и 77 и т. п.).
2. **Общие обороты:** каждые `minPhraseWords` (5) одинаковых ключей подряд в разных местах — затравка; пара расширяется в обе стороны, пока слова похожи (сходство ≥ `wordSimilarity`, 0,8), и обрезается так, чтобы начинаться и кончаться на одинаковых словах. Каждое место — внутри одной суры: оборот не «приклеивается» через конец суры к началу следующей. Каждый наибольший оборот — одна пара; перекрывающиеся места пропускаются.

`verified = 0` у всех пар: специалист их не проверял, показывать их как «проверенные» нельзя. Пара хранится один раз: `a_from < b_from`, зеркальной пары нет.

**Размер:** обе таблицы малы — их можно держать в приложении вместе с текстом, отдельный пакет не нужен.

### Ограничения

- Пары — только по совпадению ключей подряд: перестановка слов или вставка слова внутри оборота разбивает его на части.
- Короткие общие обороты (меньше 5 слов, кроме целых аятов) не попадают — иначе пар вроде «Аллах Прощающий, Милосердный» были бы тысячи.
- Пары не проверены специалистом (`verified = 0`); справочные пары по УП-05 в V1 — после проверки.

## Манифест пакетов (O05)

`bin/manifest.dart` собирает манифест по ТЗ 12.3 из готовых архивов и подписывает его Ed25519:

```bash
dart run tools/content_build/bin/manifest.dart --spec packages.json --files <папка с архивами> --key-id main-2026 --key-file <путь вне репозитория> --out manifest.json
```

- `packages.json` — что входит в манифест: `{"packages": [{"id", "kind", "version", "file", "url", "license", "minAppVersion", "dependsOn"}]}`. Размер и SHA-256 инструмент считает сам по файлу `file` из `--files`.
- Подписывается канонический JSON без `signature` (ключи по алфавиту, без пробелов, только целые числа) — то же правило, что у проверки в `packages/content`. Совпадение проверяет тестовый манифест: его делает этот инструмент, а проверяет `content`.
- **Закрытый ключ — только снаружи** (ТЗ 8.10): файл вне репозитория (`--key-file`) или переменная `SUDUR_MANIFEST_SIGNING_KEY` (base64 от 32 байт). Настоящий ключ из файла внутри репозитория инструмент не примет.
- `--new-key <путь вне репозитория>` с `--key-id` — создать новый ключ и напечатать открытый ключ для приложения; `--print-public-key` — напечатать открытый ключ существующего.
- Тестовые ключи (`test-…`) — только с `--allow-test-key`. Так собран тестовый манифест:

  ```bash
  dart run tools/content_build/bin/manifest.dart --spec packages/testing/fixtures/manifest/packages.test.json --files packages/testing/fixtures/manifest --key-id test-main --key-file packages/testing/fixtures/manifest/test-keys.TEST-ONLY.json --allow-test-key --issued-at 2026-11-18T00:00:00Z --out packages/testing/fixtures/manifest/manifest.test.json
  ```

Как выпускать пакеты и что делать при компрометации ключа — в README [`packages/content`](../../packages/content/README.md).

## Проверки

| Проверка | Требование |
|---|---|
| В каждом источнике указан идентификатор лицензии, иначе конфигурация не читается | ПР-02 |
| В тексте 114 сур и 6236 аятов | ПР-04 |
| Контрольная сумма канона совпадает с закреплённой в конфигурации | ПР-04 |
| Деление каждого из 6236 аятов на слова без потерь: слова через пробел дают исходный текст | 4.8 |
| Число аятов суры и число слов каждого аята совпадают у текста и разметки | ПР-04 |
| Охват сборки полный: первый и последний аят совпадают с закреплёнными в конфигурации (`expected.firstAyah` = 78:1, `expected.lastAyah` = 79:15 — край страниц 582–583 печатного мусхафа); между ними нет пропущенных аятов; охват начинается сверху первой страницы (или с начала суры) и заканчивается на последней строке последней страницы. Закрепление нужно: если пропал последний аят, предыдущий может тоже кончаться на последней строке | ПР-04 |
| У каждого слова и знака конца аята есть страница из сборки, строка 1–15 и знак шрифта | ПР-04 |
| Пустые строки страницы — только заголовок суры и басмала перед началом суры | 12.2 |
| Шрифт — файл TrueType | — |

**Контрольная сумма канона** — SHA-256 от строк `сура|аят|текст\n` по всем аятам по порядку. Обёртка файла (уведомление с годом, XML) в неё не входит, поэтому смена года в уведомлении Tanzil её не меняет, а изменение любой буквы — меняет. Если сумма изменилась, текст на сайте обновился: до обновления закреплённого значения его проверяет специалист (ПР-03). Сумма самого файла пишется отдельно (`textFileSha256`).

## Как текст делится на слова

Текст аята не меняется ни на один символ. Слово — кусок текста между пробелами. В Tanzil знаки паузы и знак земного поклона стоят отдельными токенами через пробел; такой токен (все символы из диапазона U+06D6–U+06ED) присоединяется к предыдущему слову вместе с пробелом. Поэтому слова аята через пробел дают исходный текст байт в байт — это проверяется на всех 6236 аятах.

`word_index` — сквозной номер слова по всему тексту Tanzil при таком делении (всего 77 433 слова). Для сур 78 и 79 число слов в каждом аяте совпадает с разметкой.

## Схема (ТЗ 12.2, ADR 0004)

- Текст и разметка раздельно: у слова либо есть строка в `word_layout`, либо нет — пустых полей «страница неизвестна» нет. Разметку можно заменить или добавить другую по `layout_id`, не трогая текст.
- `juz`, `hizb`, `sajda` у аята и место ниспослания у суры заполнены только там, где их дал источник разметки (страницы сборки); в остальных — пусто.
- `ayah_layout.end_*` — где и каким знаком рисуется конец аята; `line.surah` — номер суры для строк заголовка и басмалы (ADR 0002).
- `line_position` считает слова и знаки конца аята вместе — это порядок знаков в строке.
- `surah.name_ru`, `name_kk`, `name_uz` пусты: лицензированного источника нет (TODO_CONTENT).
- `passage_default` и `similar_pair` вычисляются из текста Tanzil (см. «Производные данные»); `tajweed_mark` пока не собирается.

## Ограничения v0

- **Разметка не из файла QUL.** Скачивание базы разметки с qul.tarteel.ai требует входа в учётную запись, поэтому разметка и коды знаков берутся из открытого API Quran.com v4 (`mushaf=1`, KFGQPC V2) — это те же данные, что показывает QUL. Если владелец скачает базу QUL вручную, можно добавить второй источник.
- **Признак `centered`** в API не передаётся: `true` только у басмалы. Вид пустых строк определяется правилом (имя суры, затем басмала, если она есть в Tanzil). Для страниц 582–583 и то и другое сверено с предпросмотром страниц на QUL: имя суры — строки 582:1 и 583:8, басмала (по центру) — 582:2 и 583:9, строки аятов не центрированы. Заголовок суры внизу страницы, когда сура начинается на следующей, не поддержан — сборка остановится с ошибкой.
- Права на разметку и шрифты не подтверждены (ТЗ 6.1, статус «Проверить»): сборка только для прототипа.
- Параметры выгрузки Tanzil — значения по умолчанию на странице загрузки: знаки паузы, знак поклона, надстрочный алиф, татвиль под надстрочным алифом.
