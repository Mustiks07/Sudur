# eval

Оценка следования и проверки на наборе записей, на компьютере.

- **Владелец:** Opus
- **Задачи:** [M01](../../docs/tasks/M01-eval.md), [C09](../../docs/tasks/C09-eval-ci.md)
- **ТЗ:** 5.3 (КЧ-01…КЧ-09), 5.5, 12.6, 14.2, 15.4 (М-01)

Правила: [`AGENTS.md`](../../AGENTS.md). Публичный интерфейс — только `lib/eval.dart`; внутренности — в `lib/src/`.

## Команда

Из корня репозитория:

```bash
dart run tools/eval/bin/eval.dart --corpus <папка с записями> --model <id модели>
```

В папке (вне репозитория) лежат пары файлов по ТЗ 12.6: `<id>.ann.json` — разметка, `<id>.<model>.asr.jsonl` — результаты распознавания. Отчёт пишется в `build/eval/<model>/report.md` и `report.json`.

| Параметр | Что это | По умолчанию |
|---|---|---|
| `--content` | Текст из `tools/content_build`: весь Коран (`text.json`, формат 2, ADR 0004) или страницы (`content.json`, формат 1); вид файла определяется по полю `kind` | `packages/testing/fixtures/quran_text.json` — весь Коран |
| `--normalizer` | `normalizer.json` пакета модели | встроенный (ТЗ 10.1) |
| `--thresholds` | `thresholds.json` пакета модели: параметры следования и окно самоисправления | встроенные (ТЗ 12.4) |
| `--acceptance` | Пороги приёмки, группы, бутстреп, допуски CI | [`config/acceptance.json`](config/acceptance.json) |
| `--out` | Папка отчёта | `build/eval/<model>` |
| `--no-check` | Только следование: показатели проверки — «нет данных» | проверка включена |
| `--rules-version` | Версия правил для поля `versions` событий проверки (ПО-11) | `version` из `thresholds.json`, иначе `builtin` |
| `--baseline` | Прошлый `report.json` для сравнения | — |
| `--ci` | Код выхода 1, если показатель упал сильнее допуска относительно `--baseline` (ТЗ 5.5) | — |

Записи, разметку людей и результаты распознавания настоящих записей в репозиторий не кладём.

## Как считается

1. Каждая запись прогоняется так же, как в сессии на телефоне: результаты распознавания по порядку → `follow`; каждая новая окончательная часть пути и кандидаты перескока сразу → `check`; в конце `finish()` у обоих. Параметры следования и проверки — из `thresholds.json` (или встроенные ТЗ 12.4). Результат одинаков при каждом запуске (бутстреп — с фиксированным зерном из конфигурации).
   - Паузы для запинок: промежуток между концом окончательного результата отрезка и началом следующего отрезка передаётся в `check` как пауза VAD.
   - Качества сигнала в наборе записей нет (ТЗ 12.6), поэтому `SignalQuality` в прогон не подаётся.
   - Версии в событиях: модель — из `info` результатов распознавания, правила — `--rules-version`, текст — `contentVersion.version` файла `--content`.
2. Для каждой записи считаются числители и знаменатели; показатели любой группы и выборки бутстрепа — из сумм.
3. Слова со статусом `unclear` не входят ни в один показатель, а события проверки, которые задевают такое слово, не участвуют в оценке ошибок (ни в точности, ни в ложных тревогах, ни в отказах): о таком слове судить нельзя.

| ID | Показатель | Числитель / знаменатель |
|---|---|---|
| КЧ-01 | Открыто на своём месте | открытые среди прочитанных чисто (`correct`, `repeated`) / прочитанные чисто |
| КЧ-02 | Открыто непрочитанное | открытые, которые не читались (`omitted`, `substituted` или нет в разметке) / все открытые |
| КЧ-03 | Точность | подтверждённые ошибки на настоящих ошибках / все подтверждённые ошибки |
| КЧ-04 | Полнота пропусков; замен — отдельно | пропущенные слова, на которых есть подтверждённый **пропуск** / все пропущенные; заменённые слова, на которых есть подтверждённая **замена** / все заменённые. Вид события должен совпадать с разметкой |
| КЧ-05 | Ложные тревоги на 1000 слов | подтверждённые ошибки не на настоящих ошибках × 1000 / прочитанные чисто |
| КЧ-06 | Отказы | слова в событиях `unverified` / все слова; только записи нормального качества (`normalNoise`) |
| КЧ-07 | Самоисправления | слова `selfCorrected`, исправленные в окне, в событиях `corrected` / все `selfCorrected`, исправленные в окне |
| КЧ-08 | По группам | все показатели по каждой группе; точность ≥ порога в каждой **обязательной** группе (см. ниже) |
| КЧ-09 | Интервалы | бутстреп **по людям**: выборка людей с возвращением |

Подробности сопоставления:

- Считается последнее состояние каждого события. Подтверждённая ошибка — `confirmed` (или `disputed`) у пропуска, замены, лишнего слова, перескока.
- Для точности (КЧ-03) пропуск или замена настоящие, если хоть одно их слово размечено как `omitted` или `substituted` (вид здесь не сверяется: место ошибки найдено верно).
- **Самоисправление и окно.** Окно — `selfCorrectionWords` слов и `selfCorrectionMs` мс из `thresholds.json` модели (ТЗ 12.4; по умолчанию 2 слова и 2500 мс), то же, что у `check`. Исправление в окне считается, если оба значения не больше окна.
  - Слово `selfCorrected`, исправленное **в окне**: подтверждённая ошибка на нём — ложная тревога, `check` должен был сказать «исправлено» (ПО-05). Такие слова — знаменатель КЧ-07.
  - Исправленное **после окна**: по ТЗ 10.5 это новая попытка, подтверждённая ошибка на нём настоящая. В КЧ-07 такие слова не входят.
  - Нет данных о времени исправления — считается исправленным сразу (в окне).
- Лишнее слово и перескок сопоставляются с разметкой по времени (`insertions`, `jumps`) с допуском `timeToleranceMs`.
- Нет знаменателя (например, в чтении нет ни одной ошибки) — «нет данных», а не 0% и не 100%.

**Режим выпуска (ТЗ 5.3):** Г — не прошли КЧ-01 или КЧ-02; В — не прошли (или нет данных) точность или ложные тревоги; А — прошло всё, включая каждую группу; иначе Б.

**Сравнение:** изменение каждого показателя в процентных пунктах (для КЧ-05 — в единицах на 1000). Допуски для `--ci` — в `ciMaxDropPp` конфигурации: точность 1 п. п., полнота 2 п. п. (ТЗ 5.5) и предложенный мной КЧ-01 — 1 п. п.

## Формат разметки: что уточнено

ТЗ 12.6 оставляет `jumps` пустым массивом. Здесь элемент перескока: `{"fromWordKey": "78:3:1", "to": "79:1:1", "startMs": 5000, "endMs": 7000}`. Строка `.asr.jsonl` — поля `RecognitionResult` с теми же именами, `info.output` — имя значения (`uthmaniLettersNoDiacritics`).

**КЧ-02, точная формула:** `открытые слова, которых не было в чтении / все открытые слова`. «Не было в чтении» — слово размечено как `omitted` или `substituted` либо его нет в разметке; слова `unclear` не входят ни в числитель, ни в знаменатель. Знаменатель — все слова, открытые по услышанному (`WordRevealed` с причиной `heard`), а не все слова отрывка.

**Время самоисправления.** У слова `selfCorrected` — поле `correction`: после скольких слов и через сколько миллисекунд пришло исправление (от начала ошибочного прочтения до начала исправления):

```json
{ "wordKey": "78:2:2", "status": "selfCorrected", "startMs": 2100, "endMs": 3300,
  "correction": { "afterWords": 1, "afterMs": 600 } }
```

`afterWords` = 1 — исправление сразу следующим словом. Если исправление пришло позже окна (`afterWords` > `selfCorrectionWords` или `afterMs` > `selfCorrectionMs`), это новая попытка: подтверждённая ошибка на слове считается настоящей.

## Состояние

- Считаются все показатели КЧ-01…КЧ-09: следование (`follow`) и проверка ошибок (`check`).
- Окно самоисправления для оценки — то же, с которым работает `check` (`CheckParams` из `thresholds.json`).
- **Обязательные группы КЧ-08** заданы в `groups` файла `config/acceptance.json`: родной язык `ru`/`kk`/`uz`, пол `m`/`f`, класс телефона `budget-android`/`mid-android`/`iphone`, шум `quiet`/`noisy`. Классы телефонов в ТЗ не перечислены поимённо — взяты по эталонному набору НФ-03 (Android 3 / 4–6 ГБ и iPhone); меняются в конфигурации.
- Каждое обязательное значение всегда есть в отчёте. Если записей с ним нет, его показатели — «нет данных», в отчёте есть строка «Нет записей в обязательных группах» (в JSON — `missingGroups`), и режим «А» невозможен. Значения, которые встретились в наборе сверх обязательных, тоже показываются.
- Режим «А» требует данных во всех обязательных группах: группа без записей или без единой подтверждённой ошибки даёт точность «нет данных», и КЧ-08 не считается пройденным.
- Запись с пустым файлом результатов распознавания прогоняется без событий проверки и не отключает показатели проверки для всего набора.

## Весь Коран (S03)

По умолчанию следование и проверка работают на тексте всего Корана (ADR 0004), как в приложении: перескок в любое место Корана ищется по всему тексту.

Тесты `test/whole_quran_test.dart` — синтетические записи по тексту всего Корана (услышанные слова — ключи канонических слов, ничего не набрано вручную):

- **перескоки** в далёкую суру (2:255) и с неверно расслышанными буквами (36:12–13), затем возврат в отрывок: КЧ-01 = 100 %, КЧ-02 = 0 %, перескоки подтверждены, точность 100 %, ложных тревог нет;
- **похожий аят в другой суре** вместо места дальше в отрывке: слова отрывка не открываются (КЧ-02 = 0 %);
- **повторяющиеся аяты суры 55**: чистое чтение 55:1–30 открывается на своих местах, ложных тревог нет;
- **КЧ-01 и КЧ-02 не ухудшились**: тот же набор по суре 78 (чистые чтения и перескок в суру 79) даёт на тексте всего Корана те же значения, что на страницах 582–583.

## Набор против ухудшения качества в CI (C09, ТЗ 5.5)

Изменение `follow`, `check` или `quran_text` не принимается, если точность упала больше чем на 1 п. п., полнота пропусков или замен — больше чем на 2 п. п., КЧ-01 — больше чем на 1 п. п. (`ciMaxDropPp` в `config/acceptance.json`). Показатель, у которого в эталоне было значение, а сейчас «нет данных», — тоже ухудшение.

**Шаг CI** «Quality gate» (в `.github/workflows/ci.yml`, после тестов; ≈ 1,5 с):

```bash
dart run tools/eval/bin/eval.dart --corpus tools/eval/reference/corpus --model synthetic --normalizer packages/testing/fixtures/models/normalizer.abdou.json --baseline tools/eval/reference/report.json --out build/eval/reference --ci
```

### Распознанный текст — как выдаёт модель (ТЗ 12.3)

Записи набора содержат текст **в том виде, в каком его выдаёт модель** `Abdou/quran-asr`: только 29 «голых» букв (`modelLetters` из `packages/testing`), а не канонические ключи. Оценка идёт с `normalizer.json` модели **строго по ТЗ 12.3** (`packages/testing/fixtures/models/normalizer.abdou.json`). Поэтому нормализатор, который не убирает огласовки, роняет шаг — раньше синтетические записи подавали канонические ключи, и такую ошибку ловил только телефон.

Проверено: со старым нормализатором (пустой `removeRanges`) шаг падает — КЧ-01 0 % (слова не открываются), полнота пропусков и замен 0 %, отказы 91 %. Это закреплено тестом `reference_test.dart`. Там же — сверка двух независимых реализаций правила ТЗ 12.3 на всех 77 433 словах (`normalizer.json` через `quran_text` и `modelLetters`).

### Эталонный набор

`reference/corpus/` — **только синтетические записи**: разметка и результаты распознавания, собранные из ключей слов канона (тестовый текст всего Корана). Звука, записей людей и набранного арабского текста нет. Файлы делает генератор, вручную не правятся; тест `reference_test.dart` сверяет их с генератором байт в байт.

| Запись | Что проверяет |
|---|---|
| `r01`, `r02` | Чистое чтение суры 78 |
| `r03` | Пропуски |
| `r04` | Замены: два непохожих слова и одно похожее (сходство между `simFloor` и `substitutionMax` — подтверждённая замена) |
| `r05` | Самоисправления: два в окне и одно после окна (новая попытка) |
| `r06` | Повтор слова и лишнее слово |
| `r07` | Запинка (долгая пауза внутри аята) и неразборчивое слово |
| `r08` | Перескок в далёкую суру (2:255) и возврат |
| `r09` | Перескок на похожий аят в другой суре и возврат |
| `r10` | Неоднозначность: сура 55 с повторяющимся рефреном |
| `r11` | Правильное чтение, распознанное с потерянной буквой в каждом третьем длинном слове |

Сейчас (вывод модели, нормализатор ТЗ 12.3): КЧ-01 100 % (589/589), КЧ-02 0 %, точность 100 % (10/10), полнота пропусков 100 % (3/3), замен 100 % (3/3), ложных тревог 0, отказы 2,0 % (8/392), самоисправления 100 % (2/2).

**Проверено намеренной поломкой** (в `main` не сливалось): `substitutionMax` в `check` 0,6 → 0,2 — шаг падает («КЧ-04 Полнота замен: упало на 33.33 п. п.»); `openThreshold` в `follow` 0,70 → 0,95 — шаг падает («КЧ-01 … упало на 1.36 п. п.»).

### Как обновить эталон (осознанно)

Обновлять эталон можно, только когда показатели **улучшились** или набор **расширен** — никогда, чтобы «пропустить» ухудшение.

1. Если менялся набор — пересобрать его: `cd tools/eval && dart run tool/build_reference.dart`.
2. Пересчитать отчёт и заменить эталон:

   ```bash
   dart run tools/eval/bin/eval.dart --corpus tools/eval/reference/corpus --model synthetic --normalizer packages/testing/fixtures/models/normalizer.abdou.json --baseline tools/eval/reference/report.json --out build/eval/reference
   ```

   ```bash
   cp build/eval/reference/report.json tools/eval/reference/report.json
   ```

3. В PR — отдельный коммит «eval: обновлён эталон» и в описании таблица «было → стало» по каждому показателю (из колонки «Изменение» в `build/eval/reference/report.md`) с объяснением. Любой показатель, который упал, — повод не обновлять эталон, а исправлять код. Ревьюер (Астра) проверяет это явно.
