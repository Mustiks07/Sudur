# 4. Архитектура и данные

## 4.1 Структура проекта [Р]

Один репозиторий. Приложение Flutter и отдельные пакеты Dart. Логика проверки, плана и уроков — на чистом Dart: её можно запускать и тестировать на компьютере без телефона и без Flutter.

```
app/                 Flutter-приложение: экраны, навигация, сборка зависимостей
packages/
  contracts/         события, интерфейсы, общие типы                    чистый Dart
  quran_text/        канонический текст, ключи поиска, индекс по Корану чистый Dart
  follow/            следование за чтением                             чистый Dart
  check/             проверка ошибок                                   чистый Dart
  session/           сессия чтения: связывает звук → распознавание →
                     следование → проверку                              чистый Dart
  planner/           план, FSRS, занятие на сегодня                    чистый Dart
  lessons/           движок уроков, формат пакета уроков               чистый Dart
  audio_capture/     микрофон, буфер, отсечение тишины, качество       Flutter
  asr_sherpa/        распознаватель на sherpa-onnx                     Flutter + FFI
  storage/           база данных (drift), хранилища                    Flutter
  content/           пакеты содержания: манифест, загрузка, установка  Flutter
  mushaf_view/       отрисовка страниц, скрытие и состояния слов       Flutter
  entitlements/      доступ к платным функциям                         V2
  sync/              синхронизация                                     V2
tools/
  eval/              прогон набора записей на компьютере, отчёт качества
  content_build/     сборка пакетов содержания из исходных данных
docs/adr/            записи архитектурных решений
```

Пакеты объединяются рабочей областью pub (pub workspaces) или melos — выбрать в начале разработки.

**Сборка iOS требует macOS.** Владелец работает на Windows, поэтому нужен свой Mac или облачная сборка (например, Codemagic или GitHub Actions с macOS). Для проверки скорости всё равно нужны настоящие iPhone (раздел 5.1).

## 4.3 Потоки выполнения [Р]

| Где выполняется | Что |
|---|---|
| Основной изолят | Интерфейс, модели экранов, отрисовка мусхафа |
| Изолят сессии чтения | Отсечение тишины, распознавание (sherpa-onnx через FFI), следование, проверка. Живёт, пока открыт экран чтения |
| Фоновый изолят базы | Запись в базу (drift в фоновом изоляте) |
| Система | Загрузки файлов, воспроизведение аудио в фоне, уведомления |

**Звук.** Пакет `record` отдаёт поток в основной изолят. Основной изолят только пересылает буферы в изолят сессии без копирования (`TransferableTypedData`) и не обрабатывает их. Если прототип покажет рывки интерфейса, захват переносится в нативный модуль, который пишет прямо в изолят сессии (раздел 7.2). Это поправка к ЗВ-08: поток интерфейса не обрабатывает звук, но может его пересылать.

**Условие допуска [Г]:** sherpa-onnx через FFI стабильно работает в отдельном изоляте на Android и iOS. Проверяется первым в прототипе.

## 4.4 Интерфейс распознавателя

Контракт в пакете `contracts`. Набросок, окончательный вид — после прототипа:

```dart
/// Что выдаёт модель.
enum AsrOutputKind { uthmaniLettersNoDiacritics, phonemes }

class RecognizerInfo {
  final String modelId;        // например 'abdou/quran-asr-small'
  final String modelVersion;   // версия пакета модели
  final AsrOutputKind output;
  final bool isStreaming;      // настоящий поток или имитация
  final bool hasTokenTimes;
}

class RecognitionResult {
  final String sessionId;
  final int segmentId;
  final bool isFinal;          // окончательный результат отрезка
  final String text;           // сырой текст модели, без исправлений
  final List<AsrToken> tokens; // символ и время, если модель выдаёт
  final int audioStartMs;
  final int audioEndMs;
  final int decodeMs;
  final RecognizerInfo info;
}

abstract interface class SpeechRecognizer {
  RecognizerInfo get info;
  Future<void> load(InstalledPackage model);
  Stream<RecognitionResult> get results;
  void acceptAudio(Float32List samples, int sampleRateHz, int startMs);
  void closeSegment(int segmentId);
  Future<void> dispose();
}
```

Реализации: `SherpaCtcRecognizer` (V1), тестовая заглушка, читающая сохранённые результаты (V1, для тестов), фонемный распознаватель (V2), облачный (Позже).

## 4.5 Контракт событий [Р]

Экраны получают только события сессии. Поля обязательны, если не помечены «необяз.». Идентификатор слова — `wordKey` в виде `сура:аят:слово`, как в QUL.

### Команды от экрана к сессии

| Команда | Поля |
|---|---|
| `StartSession` | диапазон (`fromWordKey`, `toWordKey`), режим (`supported`/`recall`/`test`), поведение (`gentle`/`strict`) |
| `Pause`, `Resume`, `Stop` | — |
| `RequestHint` | вид: `firstLetter`/`word`/`nextAyahStart`/`wholeAyah` |
| `DisputeEvent` | `eventId` |

### События от сессии

| Событие | Поля | Кто создаёт |
|---|---|---|
| `SessionStarted` | `sessionId`, диапазон, режим, версии модели, правил и текста | session |
| `SignalQuality` | `sessionId`, `atMs`, уровень: `ok`/`tooQuiet`/`clipping`/`noisy` | audio_capture |
| `PositionUpdate` | `sessionId`, `wordKey`, уверенность `high`/`low`, кандидаты при неоднозначности (необяз.), `atMs` | follow |
| `WordRevealed` | `sessionId`, `wordKey`, причина: `heard`/`hint`/`afterConfirm`, `atMs` | follow / session |
| `PositionLost` | `sessionId`, последнее уверенное `wordKey`, `atMs` | follow |
| `CheckEvent` | `eventId`, `sessionId`, вид: `omission`/`substitution`/`insertion`/`jump`/`repetition`/`hesitation`, состояние: `preliminary`/`confirmed`/`corrected`/`unverified`/`disputed`, затронутые `wordKey`, ожидаемый текст, распознанный текст, место перескока (необяз.), `audioStartMs`, `audioEndMs`, версии | check |
| `CheckStateChanged` | `eventId`, было, стало, причина | check |
| `HintGiven` | `sessionId`, вид, `wordKey` | session |
| `SessionFinished` | `sessionId`, итог по словам, список `eventId`, длительность, был ли звук пригоден | session |

### События обучения (пишутся в базу)

| Событие | Поля |
|---|---|
| `AttemptRecorded` | `attemptId`, `unitId`, режим, исход (`clean`/`withHints`/`corrected`/`withErrors`/`unverified`/`disputed`), подсказки, `eventId` ошибок, длительность, кто оценил (`voice`/`self`/`listener`/`teacher`), версии |
| `ReviewScheduled` | `unitId`, очередь, срок, состояние FSRS |
| `LessonStepCompleted` | `lessonId`, `stepId`, результат |

Изменение контракта — только через запись решения (раздел 7.4).

## 4.6 Как работает проверка внутри сессии

1. **Звук → буфер → качество сигнала.** При плохом сигнале — `SignalQuality`, проверка уходит в «не удалось проверить».
2. **Отсечение тишины → отрезки.** Паузы не выбрасываются: их длительность нужна для запинок.
3. **Распознавание.** Для непотоковой модели — повторное распознавание открытого отрезка каждые 400–600 мс и окончательное по закрытию отрезка (РС-05).
4. **Перевод в технический ключ.** Распознанный текст и ожидаемые слова приводятся к одному виду (раздел 10.1).
5. **Следование.** Сравнение с окном ожидаемых слов около текущей позиции; при потере — поиск в отрывке, затем по индексу всего Корана.
6. **Кандидаты событий.** Пропуск, замена, лишнее слово, перескок — сначала «предварительные».
7. **Стабилизация.** Подтверждение после контекста, самоисправление, неуверенность (ПО-03…ПО-07).
8. **Итог.** Подтверждённые события → попытка → план.

Правильный текст из базы никогда не подставляется вместо услышанного (ПО-13).

Точные версии фиксируются в начале разработки и обновляются только осознанно.

## 4.8 Данные

### Две базы [Р]

- **База содержания** — только для чтения, приходит пакетом, заменяется целиком при обновлении.
- **База пользователя** — прогресс и настройки, меняется миграциями.

### База содержания

Точные таблицы и поля — раздел 12.2; решение о раздельном хранении текста и разметки — [ADR 0004](../adr/0004-tekst-vsego-korana.md). Здесь — что и зачем хранится.

**Текст** — весь Коран (пакет `text`, 4.9):

| Таблица | Что хранит |
|---|---|
| `surah` | Номер, названия на арабском, русском, казахском, узбекском; число аятов; место ниспослания |
| `ayah` | Сура, аят, границы аята в тексте (`first_word_index`, `word_count`) и метаданные из лицензированного источника (`juz`, `hizb`, `sajda`) — необязательные, пусты, пока нет источника (12.2) |
| `word` | `word_index`, сура, аят, позиция в аяте, **канонический текст** `text_uthmani`. Ключ слова — стабильный `WordKey` (сура:аят:слово, 4.5). Страницы, строки и кода знака шрифта здесь нет — это разметка |

**Разметка страниц** — пакет `layout` (4.9), только страницы, на которые есть права (ADR 0002). `layout_id` позволяет заменить разметку или добавить другой мусхаф, не трогая текст:

| Таблица | Что хранит |
|---|---|
| `word_layout` | `layout_id`, `word_index`, страница, строка, порядок в строке (`line_position`), код знака шрифта страницы (`glyph_code`) |
| `ayah_layout` | `layout_id`, сура, аят, страница; где и каким знаком рисуется конец аята: `end_page`, `end_line`, `end_line_position`, `end_glyph_code` |
| `page`, `line` | Страницы и строки разметки, с `layout_id`: границы по словам, вид строки (аят, имя суры, басмала), центровка |

Разметка может покрывать только часть текста. Если у слова или аята нет строки в `word_layout` / `ayah_layout`, это значит только «нет разметки», а не «нет слова или аята». Прямоугольники слов не хранятся: их вычисляет `mushaf_view` при отрисовке.

**Прочее:**

| Таблица | Что хранит |
|---|---|
| Ключи и индекс для поиска | Здесь не хранятся: зависят от нормализатора модели и строятся при её установке в базе пользователя (`search_key_cache`, `ngram_cache`; разделы 10.1, 12.1) |
| `similar_pair` | Пары похожих мест (из QUL), признак «проверено специалистом» |
| `passage_default` | Разбиение на отрывки по умолчанию: 1–5 аятов, длинный аят — отдельный отрывок. Правила, связанные со страницей (не больше половины страницы, без перехода через страницу), действуют только в области, покрытой выбранной разметкой; страницу у каждого слова всего Корана не требуем. Собирается `content_build` |
| `tajweed_mark` | `word_index`, позиция буквы, правило (если есть источник с правами) |
| `content_version` | Версия, источник, лицензия, контрольная сумма канона |

Правила:

- канонический текст не меняется никогда; любые преобразования — в отдельных таблицах с обратной ссылкой на слово (`word_index` / `WordKey`);
- соответствие османского и обычного написания — по проверенной таблице, не по одному регулярному выражению;
- технические ключи нигде не показываются пользователю как текст Корана.

Переводы — отдельные базы на каждый перевод: `translation(ayah_key, text)` и запись о правах.

## 4.9 Пакеты содержания и доставка файлов (ДФ)

**Манифест** — JSON со списком пакетов: идентификатор, вид (`text`, `layout`, `font`, `audio`, `model`, `lessons`, `translation`, `config` — параметры, раздел 8.8), версия, размер, контрольная сумма SHA-256, адрес, зависимости, идентификатор лицензии, минимальная версия приложения. Манифест подписан (Ed25519), открытый ключ встроен в приложение.

**Пакет уроков** — JSON и файлы звуков и картинок. Набросок, окончательная схема — в пакете `lessons`:

```json
{
  "lessonId": "stage1-letters-01",
  "stage": 1,
  "title": { "ru": "...", "kk": "...", "uz": "..." },
  "skills": ["letter:alif", "letter:ba"],
  "steps": [
    { "id": "s1", "type": "explain", "text": { "ru": "...", "kk": "...", "uz": "..." },
      "image": "img/ba.png", "audio": "aud/ba.ogg" },
    { "id": "s2", "type": "hearAndChoose", "audio": "aud/ba.ogg",
      "options": ["ب", "ت", "ث"], "answer": "ب" },
    { "id": "s3", "type": "repeatAndCompare", "audio": "aud/ba.ogg" }
  ],
  "quiz": { "passPercent": 80, "stepIds": ["s2"] }
}
```

Правила: каждый текст — на трёх языках; ссылки на файлы — внутри пакета; содержание, которое ещё не готово, помечается `TODO_CONTENT` и не попадает в выпускной пакет (проверка `content_build`).

| ID | Требование | Очередь | Критерий приёмки |
|---|---|---|---|
| ДФ-01 | Внутри приложения при установке: база текста, разметка страниц, шрифты страниц (около 15 МБ по данным пакетов), обычный арабский шрифт, первые уроки этапа 1 — приложение работает сразу после установки без сети | V1 | Установка в режиме полёта: мусхаф и первые уроки открываются |
| ДФ-02 | Загружаются отдельно: модель (около 19–36 МБ), аудио, остальные уроки, переводы. Обновлённые шрифты и разметка тоже приходят пакетами | V1 | — |
| ДФ-03 | Перед загрузкой — проверка свободного места (размер × 2) | V1 | — |
| ДФ-04 | Фоновая возобновляемая загрузка | V1 | Обрыв сети на середине — загрузка продолжается |
