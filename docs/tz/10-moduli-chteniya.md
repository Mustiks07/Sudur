# 10. Модули чтения: подробная спецификация

Пакеты `quran_text`, `audio_capture`, `asr_sherpa`, `follow`, `check`, `session`. Для каждого: назначение, публичный интерфейс, алгоритм, состояния, ошибки, параметры. Все числа — начальные значения параметров (раздел 12.4), калибруются испытаниями.

## 10.1 `quran_text` — текст, ключи, поиск

**Назначение:** отдаёт канонический текст, технические ключи для сравнения и поиск мест по всему Корану. Работает на чистом Dart поверх базы содержания.

### Публичный интерфейс

```dart
abstract interface class QuranText {
  Word word(WordKey key);                       // канон, страница, строка
  List<Word> range(WordKey from, WordKey to);   // слова диапазона по порядку
  String searchKey(WordKey key, NormalizerId n); // технический ключ слова
  List<WordKey> findSequence(List<String> keys, {int maxResults = 10}); // по индексу
  List<SimilarPair> similarPairs(AyahKey ayah);
}

class WordKey { final int surah, ayah, word; }  // 1-based, строка вида "2:255:3"
```

### Нормализация [Р]

Ключи строятся тем же правилом, каким готовили подписи для обучения модели. Поэтому **нормализатор поставляется в пакете модели** (`normalizer.json`): список символов на удаление и таблица замен. Ключи для каждого нормализатора строятся при установке модели и хранятся в базе пользователя (`search_key_cache`), а не в базе содержания.

Базовые шаги (если пакет модели не задаёт иного):

1. Unicode NFC.
2. Удалить татвиль (U+0640).
3. Удалить огласовки (U+064B–U+0652) и знаки чтения Корана (U+06D6–U+06ED).
4. Обработку надстрочного алифа (U+0670), вариантов алифа (أ إ آ ٱ), хамзы, ى/ي, ة/ه — строго по таблице модели.
5. Удалить пробелы внутри слова.

**Запрещено:** показывать ключ пользователю; изменять канон; нормализовать регулярным выражением без таблицы.

### Индекс последовательностей

Для каждого нормализатора: ключи из 3 подряд идущих слов (параметр `ngramSize`) → список мест. Строится при установке модели, около 77 тысяч записей. Поиск: распознанные слова режутся на тройки, места с наибольшим числом совпавших троек — кандидаты.

### Сходство слов

`similarity(a, b) = 1 − levenshtein(a, b) / max(len(a), len(b))` по символам ключа; 1 — совпадение, 0 — ничего общего.

## 10.2 `audio_capture` — микрофон

**Назначение:** даёт поток звука 16 кГц моно, отрезки речи и оценку сигнала.

### Конвейер

```
record (PCM16, 16 кГц, моно, кадр 20–40 мс)
  → основной изолят: TransferableTypedData → изолят сессии
  → Float32 [-1; 1]
  → кольцевой буфер 30 с
  → VAD (Silero через sherpa-onnx)
  → отрезки: начало, конец, длительность пауз
  → оценка сигнала по окну 1 с
```

### Оценка сигнала

| Состояние | Условие (параметры) |
|---|---|
| `tooQuiet` | Средний уровень речи ниже −42 дБFS дольше 3 с |
| `clipping` | Больше 1% отсчётов на пределе за 1 с |
| `noisy` | Уровень в паузах выше −35 дБFS дольше 3 с |
| `ok` | Иначе |

### Отрезки речи

- Начало отрезка — VAD видит речь; к началу добавляется 300 мс из буфера.
- Конец — пауза дольше `segmentEndPauseMs` = 700 мс или отрезок дольше `maxSegmentMs` = 15 000 мс (тогда разрез по самой тихой точке последних 2 с).
- Каждая пауза записывается с длительностью: нужна для запинок (10.5).

### Фрагменты для разбора (ЗВ-02)

При появлении предварительного события проверки сессия просит у буфера фрагмент `[начало − 3 с; конец + 3 с]` и хранит его в памяти до конца разбора.

### Прерывания

| Событие системы | Поведение |
|---|---|
| Звонок, другое приложение забрало микрофон | Сессия → `paused(reason: interrupted)` |
| Смена устройства (наушники, Bluetooth) | Перезапуск записи; при Bluetooth — предупреждение |
| Приложение ушло в фон | `paused(reason: background)` |
| Разрешение отозвано | `error(micDenied)` |

## 10.3 `asr_sherpa` — распознаватель

**Назначение:** реализует `SpeechRecognizer` (раздел 4.4) на sherpa-onnx.

### Загрузка

1. Пакет модели установлен (раздел 11.4) и проверен.
2. В изоляте сессии создаётся `OfflineRecognizer` с CTC-моделью (`model.int8.onnx`, `tokens.txt`), число потоков — `asrThreads` = 2.
3. Нормализатор и пороги из пакета модели передаются в `quran_text` и `check`.

### Имитация потока для непотоковой модели (РС-05)

```
пока отрезок открыт:
  каждые partialIntervalMs (500 мс):
    окно = последние maxPartialWindowMs (8000 мс) открытого отрезка
    результат = распознать(окно) → RecognitionResult(isFinal: false)
при закрытии отрезка:
  результат = распознать(весь отрезок) → RecognitionResult(isFinal: true)
```

Если отрезок длиннее окна, частичные результаты покрывают только конец; следование сшивает их по устойчивой части (10.4).

### Тест телефона (РС-04)

Встроенный образец 10 с. Скорость = время распознавания / 10 с.

| Скорость small | Решение |
|---|---|
| ≤ 0,3 | small |
| 0,3–0,6 | tiny, если tiny ≤ 0,3; иначе small с увеличенным `partialIntervalMs` = 1000 |
| > 0,6 у обеих | Самопроверка и чтение с поддержкой; голос не включается |

Числа — [Г], уточняются прототипом.

### Ошибки

| Ошибка | Поведение |
|---|---|
| Пакет повреждён | Откат на прежнюю версию; если её нет — самопроверка и предложение перекачать |
| Нехватка памяти при загрузке | Попробовать tiny; иначе самопроверка |
| Распознавание дольше 3 × длительности окна | Событие `deviceTooSlow`, сессия продолжается без проверки |

## 10.4 `follow` — следование

**Назначение:** по распознанным словам определяет, где человек читает, и какие слова открыть. Не решает, правильно ли прочитано.

### Входы и выходы

- Вход: `RecognitionResult`, слова диапазона с ключами, события пауз.
- Выход: `PositionUpdate`, `WordRevealed`, `PositionLost`, а также **путь выравнивания** — для `check`.

### Устойчивая часть (СЛ-08)

Распознанный текст делится на слова по разделителю модели. Устойчивыми считаются слова, которые совпали в двух подряд частичных результатах отрезка, и все слова окончательного результата. Работа идёт только с устойчивыми словами.

### Выравнивание лучом [Р]

Состояние — до `beamSize` = 5 гипотез. Гипотеза: позиция `i` (следующее ожидаемое слово), накопленная стоимость, история переходов.

Для каждого нового устойчивого слова `h` из каждой гипотезы строятся переходы:

| Переход | Новая позиция | Стоимость |
|---|---|---|
| Совпадение с `W[i]` | `i + 1` | `1 − sim(h, W[i])` |
| Пропуск `k` слов (1 ≤ k ≤ `maxSkip` = 4) и совпадение с `W[i+k]` | `i + k + 1` | `k × costSkip(1,0) + 1 − sim(h, W[i+k])` |
| Возврат к `W[j]`, `i − maxBack` ≤ j < i, `maxBack` = 8 | `j + 1` | `costBack(0,3) + 1 − sim(h, W[j])` |
| Лишнее слово | `i` | `costInsert(1,0)` |

Оставляются `beamSize` лучших гипотез. Переходы с `sim` < `simFloor` = 0,4 не строятся, кроме «лишнего слова».

### Когда открывать слово

Слово `W[i]` открывается (`WordRevealed(heard)`), когда:

1. в лучшей гипотезе есть совпадение с `W[i]` при `sim ≥ openThreshold` = 0,70;
2. эта часть пути одинакова у всех гипотез луча (или прошло ещё 2 устойчивых слова).

В режиме с поддержкой вместо открытия — подсветка текущего слова.

### Потеря позиции

Если средняя стоимость последних 4 слов лучшей гипотезы больше `lostCostThreshold` = 0,6:

1. поиск во всём выбранном отрывке по тройкам слов;
2. если не найдено — поиск по всему Корану (`quran_text.findSequence`);
3. найдено вне отрывка → передать `check` кандидата перескока; слова вне отрывка не открывать;
4. ничего не найдено → `PositionLost`, ждать следующих слов.

### Неоднозначность (СЛ-05)

Если два места отрывка дают стоимость с разницей меньше `ambiguityMargin` = 0,15, держатся обе гипотезы, `PositionUpdate` отправляется с `confidence: low` и списком кандидатов; слова не открываются до различающего слова.

## 10.5 `check` — проверка ошибок

**Назначение:** по пути выравнивания и паузам решает, где ошибки, и ведёт их состояния.

### Кандидаты из пути выравнивания

| Что в пути | Кандидат | Подтверждение |
|---|---|---|
| Переход «пропуск k слов» | Пропуск каждого из k слов | После `confirmContextWords` = 2 следующих совпадений с `sim ≥ strongMatch` = 0,85 |
| Совпадение с `sim < substitutionMax` = 0,60 | Замена | Следующие 2 слова совпали сильно, самоисправления в окне не было |
| Совпадение с `0,60 ≤ sim < 0,85` | «Не удалось проверить» | Не подтверждается как ошибка |
| «Лишнее слово» | Лишнее | Если слово совпадает с соседним ожидаемым — это повтор, не ошибка |
| Найдено место вне отрывка, совпало ≥ `jumpMinWords` = 3 слова подряд | Перескок | Сразу после совпадения 3 слов |
| Возврат назад | Повтор (сигнал) | Не ошибка |
| Пауза между словами внутри аята дольше `hesitationPauseMs` = 2500 мс и дольше 3 × личной медианы пауз | Запинка (сигнал) | Не ошибка |

### Самоисправление

Если после кандидата пропуска или замены в окне `selfCorrectionMs` = 2500 мс или `selfCorrectionWords` = 2 слова в пути есть возврат к этому слову и совпадение с `sim ≥ 0,85` — событие становится `corrected`.

### Плохой сигнал

Если на время слова приходится `SignalQuality ≠ ok` или распознавание опоздало (`deviceTooSlow`), любой кандидат на этом слове становится `unverified`.

### Состояния события

```
preliminary ──(подтверждено)──────────→ confirmed ──(«Не согласен»)──→ disputed
     │──(исправился в окне)───────────→ corrected
     │──(мало контекста, плохой звук,
     │   конец сессии)────────────────→ unverified
```

Из `confirmed` в `corrected` нельзя: исправление после подтверждения — это новая попытка.

### Строгое поведение (ЭЧ-05)

При `confirmed` (пропуск или замена) `session` перестаёт открывать слова дальше ошибочного, пока не будет совпадения с этим словом при `sim ≥ 0,85` или не взята подсказка. Через 3 неудачи или 15 с — предложение подсказки.

### Правило ПО-13

В каждом событии есть распознанный текст как есть. Ни один шаг не заменяет его ожидаемым словом.

## 10.6 `session` — сессия чтения

**Назначение:** связывает звук, распознавание, следование и проверку; принимает команды экрана; выдаёт события.

### Состояния

```
idle → preparing → ready → listening ⇄ paused → finishing → finished
                     ↘ error(modelMissing | micDenied | deviceTooSlow)
```

| Состояние | Что происходит |
|---|---|
| `preparing` | Загрузка модели в изолят, подготовка диапазона и ключей |
| `ready` | Микрофон включён, ждём голос; экран показывает «Начинайте читать» |
| `listening` | Идёт обработка |
| `paused` | Причина: человек, звонок, фон; обработка остановлена, состояние сохранено |
| `finishing` | Дораспознавание открытого отрезка; предварительные события без контекста → `unverified` |
| `finished` | Итог `SessionFinished`; попытки по единицам (ПЛ-12) |

### Итог сессии

Для каждого слова диапазона — одно из: прочитано, прочитано с подсказкой, ошибка, исправлено, не удалось проверить, не прочитано (человек остановился раньше). «Не прочитано» не считается ошибкой.

### Подсказки

| Вид | Что открывается | Как учитывается |
|---|---|---|
| `firstLetter` | Первая буква следующего слова (из канона) | Подсказка |
| `word` | Следующее слово целиком | Подсказка, слово помечено «открыто подсказкой» |
| `nextAyahStart` | Первое слово следующего аята | Подсказка |
| `wholeAyah` | Текущий аят целиком | Подсказка; аят в итоге — «с подсказкой» |

### Параллельно с чтением

- Каждые 30 с и при паузе состояние сессии сохраняется (НФ-21).
- Экран не гаснет (ЭЧ-09).
- Пока играет аудио чтеца, звук не обрабатывается (ЗВ-09).
