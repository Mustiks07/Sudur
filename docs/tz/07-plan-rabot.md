# 7. План работ, правила, риски

## 7.1 Этапы

Сроки не указаны: они зависят от испытаний и от того, как быстро готовится содержание курса. После этапов 1 и 2 план уточняется. Разбивка этапов на задачи — раздел 15.

| Этап | Что делаем | Результат | Можно параллельно с |
|---|---|---|---|
| **0. Подготовка** | Юридическое заключение о сборе записей (ЮР-01); реестр прав; найти специалиста на разовую работу: проверить и озвучить уроки, проверить мусхаф; владелец записывает первые тестовые чтения с намеренными ошибками; интервью с 20–30 людьми из Казахстана, Узбекистана и русскоязычной аудитории; закупить эталонные телефоны; начать сбор пилотных записей; аккаунты разработчика Apple и Google Play; Mac или облачная сборка для iOS; переводчики текстов уроков на казахский и узбекский | Можно собирать записи; есть преподаватель; понятны реальные трудности людей | 1 |

Прототип самого сложного экрана** | Flutter, одна сура: микрофон → изолят сессии → отсечение тишины → sherpa-onnx с `quran-asr-small` и `-tiny` → следование → страница со скрытыми словами, которые появляются; рядом — отрисовка нескольких страниц мусхафа шрифтами страниц | Ответы на И-3 и И-6: задержки, память, работа FFI в изоляте, нужен ли нативный захват звука | 0, 2 |

**Содержание курса** (тексты, звуки, упражнения) владелец и специалист готовят с этапа 0 параллельно разработке. Без него этап 6 не закончится.

**Срок.** К Рамадану не привязываемся (решение владельца): выпуск, когда готово и проверено всё из V1.

**Новые модули по опросу владельца** — аккаунт и сервер, английский, цели, серии и достижения, намаз и кибла, дуа, тафсир, фонемная модель — задачи Н-01…Н-14 в разделе 16.15.

### Очередь V2 (порядок предварительный)

1. Синхронизация и необязательный аккаунт — после ЮР-02.
2. Покупки: подписка и разовая покупка.
3. Личные пары похожих аятов, подробный анализ трудностей, история.
4. Проверка огласовок и звуков голосом — при успешном И-5.
5. Режим бумажного мусхафа, слушающий рядом, полный маршрут восстановления.
6. Цветной таджвид, текстовый режим мусхафа, перевод слова.
7. Время намазов, виджет, узбекская кириллица.

## 7.2 Запасные планы

| Если | То |
|---|---|
| Модель не проходит пороги | Режимы выпуска Б, В или Г (раздел 5.3); параллельно — дообучение на собранных записях |
| Рывки интерфейса из-за звука во Flutter | Нативный модуль захвата звука за тем же интерфейсом |
| sherpa-onnx не работает стабильно в изоляте | Нативный сервис распознавания на Kotlin и Swift за тем же интерфейсом `SpeechRecognizer` |
| Шрифты страниц тормозят или не помещаются в память | Один шрифт Digital Khatt с собственной вёрсткой строк |
| Нет прав на перевод | V1 без перевода на этом языке |
| Содержание курса не готово | Запуск с готовыми уроками и честным указанием их числа |
| Телефон не тянет распознавание | Самопроверка и чтение с поддержкой по видимому тексту |

Менять всю архитектуру из-за одной части не нужно: заменяется только проблемный модуль.

## 7.3 Правила записи решений

Каждое крупное решение — файл в `docs/adr/` с полями: контекст, решение, рассмотренные варианты, последствия, что должно случиться, чтобы решение пересмотреть. Решения К1–К15 из раздела 0 переносятся туда первыми.

## 7.4 Правила для ИИ-агентов

**Порядок работы:**

1. Одна задача — один пакет или один экран, с тестами.
2. Перед началом агент читает: свой раздел ТЗ, пакет `contracts`, записи решений в `docs/adr/`.
3. В описании изменения — номера закрытых требований и как проверено.

**Запреты:**

- менять `contracts` без записи решения, утверждённой владельцем;
- править базу текста Корана или пакеты содержания вручную: только через `tools/content_build` из источников реестра прав;
- создавать языковой моделью арабский текст, переводы смыслов и звук. Черновики объяснений для уроков ИИ готовить может, но в пакет они попадают только после проверки специалистом; до проверки — метка `TODO_CONTENT`;
- писать пороги и параметры числами в коде: только в конфигурации;
- писать в журналы и отчёты о сбоях звук и распознанный текст;
- добавлять зависимость без короткого обоснования и проверки лицензии.

**Автоматические проверки при каждом изменении:**

| Проверка | Когда |
|---|---|
| Форматирование, анализатор без предупреждений, тесты | Всегда |
| Правила зависимостей (раздел 4.2) | Всегда |
| Снимки экранов мусхафа | При изменении `mushaf_view`, шрифтов, разметки |
| Прогон набора записей, сравнение с прошлым результатом | При изменении `follow`, `check`, `quran_text` |
| Тесты миграций | При изменении `storage` |
| Проверка схемы манифеста и лицензий пакетов | При изменении `content`, `content_build` |

**Обязательная проверка человеком:** `contracts`; всё, что касается текста Корана и содержания; разрешения и приватность; покупки; настройки выпуска.

## 7.5 Риски

| Риск | Вероятность | Последствие | Что делаем |
|---|---|---|---|
| Модель плохо слышит учеников с акцентом | Средняя | Ложные обвинения, потеря доверия | Пороги и режимы выпуска; сбор записей; дообучение |
| Модель «исправляет» ошибку чтеца | Средняя | Пропущенные ошибки | Испытание И-2; правило ПО-13 |
| Дешёвые телефоны не тянут | Средняя | Нет проверки голосом у части аудитории | Модель tiny, самопроверка, минимальные требования |
| Нет прав на переводы и аудио | Высокая | Меньше содержания в V1 | Реестр прав с этапа 0; запуск без отдельных компонентов |
| Преподаватель и содержание курса запаздывают | Высокая | Курс неполный | Начать с этапа 0; честный объём |
| Ошибка в тексте Корана на экране | Низкая | Серьёзный ущерб доверию | Канон не меняется; проверка специалистом всех страниц |
| Закон о данных (Казахстан, Россия) | Высокая для V2 | Нельзя запустить синхронизацию | V1 без сервера; ЮР-02 до V2 |
| Tarteel выпустит офлайн-проверку (просьба «на рассмотрении») | Средняя | Слабее одно из отличий | Отличие строится на сочетании, не на одном офлайне |
| Отказ магазина (микрофон, религиозное содержание) | Низкая | Задержка выпуска | Чек-листы магазинов, точные тексты разрешений |
| Агенты незаметно ухудшают качество | Средняя | Регрессии | Набор записей, правила зависимостей, проверка человеком |
| Нет Mac для сборки и проверки iOS | Высокая, если не решить заранее | Нельзя выпустить iOS-версию | Облачная сборка; доступ к iPhone для замеров с этапа 1 |
| Тексты уроков нужны на трёх языках | Высокая | Курс задерживается | Переводчики с этапа 0; урок не выходит без трёх версий |

Ответы владельца от 16.11.2026:

| Сбор записей | Да, с отправкой, когда появится интернет (раздел 4.12) |
| Где собирать iOS | Мак друга и облачная сборка |
| Страна компании | Казахстан |
| Чтецы | Мишари Рашид аль-Афаси и другие известные — при наличии прав |
| Россия | Да, позже |
| Обратная связь | Telegram |

Остаются открытыми:

1. Название — варианты готовит Н-19.
2. Переводы смыслов — выбор владельца (Н-21).
3. Пороги качества — утвердить после испытания моделей.
4. Узбекская кириллица — по запросам пользователей.

Решено во второй части опроса (раздел 16.17): аккаунты — на себя; содержание курса и звуки — владелец, с рекомендацией одной проверки у знающего человека; юридические и бухгалтерские тексты — ИИ, с рекомендацией одной консультации юриста; мусхаф — мединский 15 строк; первые записи — свои и знакомых.
