# Прототип P08: проверка на Samsung

Ветка `astra/p08-prototype`, база `main` — `4787485`. Прототип доступен только
через `lib/main_dev.dart`; `beta` и `prod` сохраняют каркас приложения.
Сура 78, режим «Пробую вспомнить»: `audio_capture` → `asr_sherpa` → `follow`
→ `mushaf_view`. Открытое слово не означает, что оно прочитано правильно:
`check` в этот экран не подключён.

## Установка APK и данных

1. После доставки ветки открыть PR. Дождаться зелёного CI; скачать артефакт
   `sudur-prototype-profile`, распаковать `app-profile.apk`.
2. Включить на Samsung параметры разработчика и отладку USB. Подключить телефон,
   подтвердить его ключ, проверить `adb devices`. Установить:

   ```sh
   adb install -r app-profile.apk
   ```

3. Открыть приложение один раз: оно создаст свою папку. При первом запуске
   отсутствие файлов ожидаемо; микрофон ещё не включается.
4. На компьютере из корня репозитория скачать обе модели и Silero:

   ```sh
   bash packages/asr_sherpa/tool/download_models.sh all
   bash packages/audio_capture/tool/download_silero_vad.sh
   bash app/tool/install_prototype.sh
   ```

   Скрипты P04/P05 проверяют закреплённые SHA-256. Повторную загрузку в
   существующий кеш они намеренно отклоняют; уже скачанный кеш можно использовать.
   Скрипт P08 скачивает шрифты QUL V2 для страниц 582–583 и переносит данные
   через `adb` в `/sdcard/Android/data/kz.sudur.sudur/files/prototype`.
   Приложение проверяет SHA-256 точной копии P03 и обоих шрифтов до показа;
   ASR и VAD проверяют свои файлы при загрузке. Публичных загрузок из приложения
   и установки непроверенных сетевых архивов нет.
5. Нажать «Загрузить файлы». Выбрать `small` или `tiny`. Нажать «Тест телефона»:
   модели загружаются по очереди и освобождаются, решение — по РС-04/ТЗ 10.3.
   Для медленного `small` применяется интервал частичных результатов 1000 мс;
   при рекомендации самопроверки голосовой запуск блокируется. Это тест скорости
   на детерминированном шуме, не оценка точности распознавания речи.
6. «Начать»: приложение объясняет использование микрофона, затем запрашивает
   разрешение Android. Читать суру 78; скрытые слова должны появляться по
   услышанному. Страницы листаются горизонтально. «Завершить» ждёт последние
   результаты ASR и следования, затем освобождает модели и звук.

При отказе в разрешении доступна кнопка самопроверки: она открывает текст
без оценок правильности. Уход в фон и прерывание записи завершают сессию;
возврат не включает микрофон автоматически. Для нового занятия снова «Начать».

## WAV и журнал

Использовать собственный согласованный файл: PCM16, mono, 16000 Гц. Например:

```sh
bash app/tool/install_prototype.sh /absolute/path/reading.wav
```

Для замены только записи без повторной установки остальных файлов:

```sh
adb push reading.wav /sdcard/Android/data/kz.sudur.sudur/files/prototype/input.wav
```

Включить переключатель `input.wav`, нажать «Начать». P05 подаёт файл в реальном
темпе через тот же VAD. По концу файла сессия завершается после обработки очереди.
Приложение не создаёт записей микрофона: WAV заранее сохранён и установлен владельцем.

После завершения — «Поделиться журналом». Android передаёт `sudur-timing.json`
через временное разрешение только на этот файл. В журнале нет PCM, распознанных
строк, канонического текста или идентификаторов говорящего. Только типы событий,
время, номера отрезков, числовые ключи слов, число сэмплов, длительности декодирования
и кадров. Журнал до экспорта хранится в памяти; лимит переполнения отражён
в `droppedEvents`. Такой замер нельзя засчитывать.

Временные шкалы различаются:

- `wallUs` — монотонные микросекунды от начала прогона;
- `audioMs`/`startMs` — миллисекунды на шкале записи;
- `captureStart` — запрос запуска, включая загрузку VAD;
- `captureStarted` — подтверждение запуска подачи; его используют как начало WAV;
- `WordRevealed.wallUs` — получение события следования на основном изоляте;
- `durationUs` у `asrPartial`/`asrFinal` — измеренное P04 время декодирования;
- `frame` — длительности build/raster/totalSpan из Flutter FrameTiming.

Ключ слова кодируется как `surah * 1000000 + ayah * 1000 + word`.
Запуск новой сессии заменяет предыдущий журнал: сначала сохранить нужный файл.
Тест телефона и загрузку страницы также экспортировать **до** нового запуска.

Локальная сводка, без чтения звука:

```sh
python3 app/tool/summarize_trace.py sudur-timing.json --annotation reading.ann.json
```

Разметка — ТЗ 12.6: `words[].wordKey`, `status`, `endMs`. Скрипт считает p95
задержек открытых размеченных слов и отдельно число неоткрытых слов. Нельзя
объявлять успех по задержке, скрыв неоткрытые слова. Отрицательные задержки требуют
проверки синхронизации. `captureStarted` — подтверждение команды, а не аппаратная
метка первого сэмпла: для окончательной приёмки НФ-10 отдельно оценить эту погрешность.

## Что проверить владельцу

| Проверка | Действие и результат |
|---|---|
| Основной сценарий | small и tiny: сура 78 от начала и с середины; слова открываются, пропуски не дорисовываются ожидаемым текстом |
| Завершение | Остановить на середине фразы и дождаться финального результата; WAV до конца; повторить запуск. Нет зависания или событий прошлого занятия |
| Разрешения и прерывания | Первый запрос, отказ, отзыв разрешения, Home/возврат, блокировка экрана, звонок, смена проводной/Bluetooth-гарнитуры. Микрофон не возобновляется сам |
| Регрессии P05 | До и после паузы сравнить начало отрезка, отсутствие обрезанного pre-roll и непрерывность времени; эти проверки пока требуют тестового приложения/лога P05, P08 завершает сессию при прерывании |
| НФ-10 | WAV с размеченными концами слов; p95 ≤ 1000 мс, отдельно пропущенные слова и погрешность начала подачи; затем ручной опыт с микрофоном |
| НФ-12 | 20 минут WAV: нет ошибок/переполнения очереди/потерь; p95 отношения времени обработки к звуку ≤ 0,7. В сводке суммируется стоимость всех частичных и финальных декодирований по минутам |
| НФ-13 | Android Studio Profiler или `adb shell dumpsys meminfo kz.sudur.sudur`: базовая память, пик с ASR, после остановки. Дополнительная память ≤ 250 МБ; отдельно учитывать журнал и WAV в памяти |
| НФ-18 | Холодная загрузка: `pageLoadStarted` → `pageFirstFrame` ≤ 300 мс; листание с Flutter DevTools, пропущено ≤ 1% кадров. Журнал frame — вспомогательный, частоту экрана брать с телефона |
| Экспорт | Сохранить JSON, проверить чтение скриптом; отсутствуют звук/распознанный текст; после переключения модели журнал сохраняет модель завершённого прогона |

Для НФ-12 сравнение задержки на 1-й и 20-й минутах требует соответствующей
разметки и ещё не открытых слов: простое повторение уже открытой суры не создаёт
повторных `WordRevealed`. Не считать отсутствие поздних событий нулевой задержкой.
При необходимости отдельного длительного сценария — зафиксировать его до приёмки
этого критерия. Числа производительности на Samsung ещё не измерены.

Записывать результат вне репозитория: модель Samsung, Android, RAM, частота экрана,
версия APK/commit, модель ASR, cold/warm, источник звука, длительность, p95,
пропуски, пик RAM, сбои. Журналы и записи людей не добавлять в git.

## Ограничения и доставка

P03 не содержит глифов заголовков сур и басмалы; соответствующие строки остаются
пустыми, на экране есть `TODO_CONTENT`. Их не дорисовываем вручную. На странице 583
сохранена исходная разметка начала суры 79; следование ограничено сурой 78.
Канон — Tanzil, https://tanzil.net, CC-BY-3.0, без изменений; уведомление и источники
сохранены в `content.json` и `tools/content_build/ATTRIBUTION.md`.
Шрифты — KFGQPC через QUL; как в P03, условия публичного распространения ещё
не подтверждены: шрифты и модели не входят в git/APK.

RU интерфейс прототипа доступен во всех четырёх ARB; en/kk/uz явно помечены
`TODO_TRANSLATION`. Полная локализация и заголовки — до публичного выпуска.

Прямые зависимости app — существующие пакеты workspace и `crypto 3.0.6`
(BSD-3-Clause, уже в lockfile) для проверки канонического файла и шрифтов.
Новые внешние библиотеки не добавлены. Android FileProvider используется из
существующей AndroidX-зависимости Flutter.

Основа — API P05 из текущего main. PR №12 несовместимо добавляет `sessionId`
в конструктор захвата и меняет тип потока. Если №12 сливается раньше P08,
нужно применить прилагаемый патч совместимости `app/tool/after_pr12.patch`,
затем повторить анализатор, тесты и CI. Патч не меняет `packages/`.

После доставки: открыть `[P08] prototype`, дождаться полного CI и profile APK,
проверить на Samsung. Только после проверки владельцем отмечать P08 завершённой.
