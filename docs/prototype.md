# Прототип P08: установка и замеры на Samsung

Прототип показывает страницы 582–583, скрывает слова и открывает их по
событиям сессии. Сборка предназначена только для закрытой проверки на телефоне.

> Пока S05 и ADR 0005 не слиты, экран использует подставную последовательность
> событий. Она проверяет интерфейс и неподвижность текста, но её цифры нельзя
> считать замерами распознавания НФ-10 и НФ-12. После подключения S05 повторите
> все шаги ниже с микрофоном и WAV.

## Как скачать и установить APK

1. Откройте запрос P08 на GitHub и дождитесь зелёной проверки CI.
2. Внизу страницы проверки откройте **Artifacts**.
3. Скачайте `sudur-prototype-profile-arm64` и распакуйте ZIP.
4. Передайте `app-arm64-v8a-profile.apk` на Samsung.
5. На телефоне разрешите установку из этого источника и откройте APK.
6. Если Android предложит заменить предыдущую тестовую сборку, подтвердите.

Это профильная arm64-сборка для измерений, а не выпуск для магазина.

## Первый запуск

1. Подключите телефон к устойчивому Wi-Fi.
2. Откройте приложение и не закрывайте его во время первой загрузки.
3. Приложение само скачает закреплённую модель `small`, канонические данные
   страниц и два страничных шрифта. Для каждого файла проверяется SHA-256.
4. Дождитесь появления двух страниц. Ничего вручную копировать не нужно.
5. Для слабого телефона можно выбрать модель `tiny`; она загрузится и
   проверится отдельно.
6. Нажмите **Тест телефона**. Запишите модель, отношение времени обработки к
   длительности и время декодирования.

Модели и шрифты лежат только в закрытом каталоге приложения и не входят в APK.
Если проверка контрольной суммы не прошла, экран покажет ошибку и кнопку
повторной загрузки.

## Проверка основного сценария

После слияния S05 требуется проверка на устройстве владельца:

1. Выберите `small`, затем повторите с `tiny`.
2. Нажмите **Начать** и разрешите микрофон после объяснения приложения.
3. Прочитайте суру 78 наизусть.
4. Проверьте, что слова появляются на своих местах, соседние слова и строки не
   сдвигаются, пауза и продолжение не теряют позицию.
5. Проверьте подсказку, остановку посреди чтения и повторный запуск.
6. Нажмите **Поделиться журналом** и сохраните JSON вместе с результатом.

Журнал содержит только типы и время событий, ключи слов и состояния. Звук,
ожидаемый текст и распознанный текст в него не попадают.

## Режим WAV

1. Поместите на телефон эталонный PCM16 WAV 16 кГц mono.
2. Нажмите **Выбрать WAV** и выберите запись через системное окно.
3. Нажмите **Начать**. После S05 файл проходит через тот же интерфейс источника
   звука, что и микрофон, в реальном времени.
4. После завершения нажмите **Поделиться журналом**.
5. Для возврата к живому чтению нажмите **Использовать микрофон**.

## Что измерить

Каждый сценарий выполните три раза для `small` и `tiny`. Телефон не заряжать во
время сравниваемых прогонов; яркость 50%, одинаковая температура и режим сети.

### НФ-10 — появление слова

Подайте размеченный WAV. Для каждого `WordRevealed` сравните `receivedAtMs` в
журнале с концом этого слова в разметке. Запишите p50 и p95. Цель p95 — не более
1,0 секунды. Затем отдельно повторите чтение через микрофон и отметьте заметные
задержки вручную.

### НФ-12 — двадцать минут

Подайте непрерывную 20-минутную запись. Проверьте отсутствие падений и потерь
звука. Сравните задержку появления слов на первой и двадцатой минутах: ухудшение
должно быть не больше 20%. Отношение обработки к длительности — p95 не больше
0,7.

### НФ-13 — память

В Android Studio откройте **Profiler → Memory**, запустите 20-минутный сценарий
и запишите память до старта и пиковое значение во время распознавания.
Дополнительная память должна быть не больше 250 МБ. Сохраните снимок графика.

### НФ-18 — мусхаф

В Flutter DevTools откройте **Performance**. Измерьте первый кадр страницы и
несколько раз перелистните 582 ↔ 583. Цель: первый показ не больше 300 мс,
пропущено не больше 1% кадров. Сохраните скриншот временной шкалы.
