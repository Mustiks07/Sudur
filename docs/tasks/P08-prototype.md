# P08 — сборка прототипа и замеры

- **Агент:** GPT-A (раньше было у Астры; передано владельцем 18.11.2026, Астра проверяет)
- **Ветка:** `gpt-a/p08-prototype`
- **Можно менять:** `app/`, `docs/prototype.md`, `.github/workflows/`; `pubspec.lock` — как следствие
- **ТЗ:** 7.1 (этап 1), 4.3, 4.5, 5.2 (НФ-10, НФ-12, НФ-13, НФ-18), 10.6, 14.4, 15.3 (П-08)

## Зачем

Первый раз владелец видит приложение на своём Samsung: открывает суру 78, текст скрыт, читает наизусть — слова появляются. И отвечаем на вопросы прототипа: успевает ли телефон, стабилен ли sherpa-onnx в изоляте, нужен ли нативный захват звука, тянет ли Flutter страницы мусхафа.

## Что сделать

1. **Экран прототипа** в `app/`: сура 78, страницы 582–583 через `mushaf_view`, режим «Пробую вспомнить» (текст скрыт). `ReadingViewModel` получает поток событий сессии (`SessionEvent` из `contracts`) и шлёт команды экрана; View только показывает.
2. **Подставная сессия сначала.** Сессию делает GPT-B (S05), договор — ADR 0005. Пока их нет — экран работает на подставной сессии, которая проигрывает заранее записанную последовательность событий. Когда S05 будет слита — подключить настоящую; подставная остаётся для тестов.
3. **Сборка зависимостей в `app/lib/config`:** `audio_capture` и `asr_sherpa` передаются в сессию через интерфейсы `contracts` (сессия сама сервисы не импортирует).
4. **Настройки прототипа:** выбор модели small или tiny и тест телефона (РС-04 — замер уже есть в `asr_sherpa`).
5. **Модель и шрифты без ручного копирования:** сборка `dev` при первом запуске сама скачивает модель (как скрипт в `asr_sherpa/tool`) и шрифты страниц 582–583 (как `content_build`), проверяет контрольные суммы и показывает прогресс. Владелец ничего не копирует на телефон. В репозиторий модели и шрифты не попадают.
6. **Режим замеров** (сборка `dev`): подача WAV-файла вместо микрофона через тот же интерфейс источника звука, журнал времени всех событий в JSON, кнопка «Поделиться журналом».
7. **Сборка в CI:** APK `profile` (arm64) как артефакт — для замеров на Samsung.
8. **`docs/prototype.md` для владельца** — по-русски, по шагам: как скачать APK из GitHub и установить, первый запуск, что сделать для замеров НФ-10, НФ-12, НФ-13, НФ-18 и куда записать результаты.

## Готово, когда

- Тесты `ReadingViewModel` на подставной сессии; виджет-тест экрана: скрытые слова открываются по событиям, не сдвигая остальные.
- APK `profile` собирается в CI и доступен как артефакт.
- После слияния S05: владелец ставит APK, читает суру 78 наизусть — слова появляются (в PR: «needs owner device check» и что именно проверить).
- Журнал замеров выгружается и читается.

## Не делать

- Не писать арабский текст: только канон из базы содержания и шрифты страниц.
- Не писать звук на диск и не логировать распознанный текст (кроме режима замеров с WAV-файлом — там журнал времени событий, без текста).
- Не менять `packages/` — если пакету чего-то не хватает, написать в PR владельцу пакета.
