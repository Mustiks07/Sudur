# PL01 — план повторений и занятие на сегодня

- **Агент:** GPT-A
- **Ветка:** `gpt-a/pl01-planner`
- **Можно менять:** `packages/planner/`; `pubspec.lock` — как следствие новых зависимостей
- **ТЗ:** 3.4 (ПЛ-01…ПЛ-12, ЗН-01…ЗН-05, таблица оценок), 3.5 (ВЗ-01…ВЗ-05, простой вариант), 3.6 (КП-01), 11.1, 12.4 (группа «План»)

## Зачем

Главное обещание приложения — «откройте, и мы скажем, что повторить сегодня, чтобы не забыть выученное». Планировщик решает, какие отрывки повторить, когда давать новое и сколько это займёт.

## Что сделать

Пакет на чистом Dart (ПЛ-10): чистые функции и неизменяемые модели, время — через внедрённые `Clock`, случайность — через `Random`. Все числа — из объекта параметров с значениями по умолчанию из ТЗ 12.4.

1. **Модели:** единица (отрывок, стык, трудное место, навык), её состояние (очередь, карточка FSRS, срок, начало «недавнего», последняя попытка и способ проверки), исход попытки (режим, результат, подсказки, способ, длительность, число слов). Модели свои, не из `storage`: базу делает GPT-B (O04), связывать их будет приложение.
2. **Очереди и переходы** — строго по ТЗ 11.1: `notStarted → learning → recent → old`, переучивание после двух «Забыл» подряд в `old`, трудное место `open → practicing → closed`, навык по FSRS.
3. **Оценка попытки** — по таблице ТЗ 3.4: «Хорошо», «Легко», «Трудно», «Забыл»; «не удалось проверить» и «оспорено» оценки не дают и срок не сдвигают; режим с поддержкой — без оценки.
4. **Сроки:** лестница `recentLadderDays` для недавнего; FSRS (пакет `fsrs`, `desiredRetention`) для старого и навыков; при переходе в старое карточка уже имеет историю (каждая оценённая попытка обновляет её).
5. **Сборка занятия на сегодня** — по алгоритму ТЗ 11.1, шаги 0–7: бюджет, вчерашнее новое, трудные места (≤ `hardSpotMaxShare`), недавнее, старое по вероятности вспомнить, новое только при остатке и малом долге (ПЛ-02, ПЛ-09); стоимость шага — по личной скорости и множителям; у каждого шага причина (ПЛ-05); итог «около N минут» (ПЛ-06); «Ещё повторить» — следующие по сроку.
6. **Новое (ЗН-01…ЗН-05):** шаги заучивания из параметров, выучено после одного чистого «Проверяю себя», стык с предыдущим отрывком, незаконченное продолжается завтра, порядок сур по умолчанию — от конца Корана.
7. **Отрывки** приходят на вход списком диапазонов слов. Таблицы `passage_default` в базе содержания пока нет (ADR 0002) — в тестах собирать отрывки из диапазонов аятов.
8. **Перерыв и восстановление:** диагностика после `breakDays` (ВЗ-01, ВЗ-02), пропущенные дни — не ошибки (ВЗ-03), новое вдвое меньше первую неделю (ВЗ-04), простой путь «знал раньше» (ВЗ-05).
9. **Карта памяти (КП-01):** состояние единицы выводится из данных по таблице ТЗ 11.1.
10. **Сессия по диапазону (ПЛ-12):** попытка создаётся для каждой единицы, прочитанной целиком.
11. **Цели (ПЛ-11):** несколько целей одновременно; правка занятия на сегодня (убрать и добавить шаг).

## Готово, когда

- Автотесты из критериев ТЗ: бюджет 5 минут и большой долг — нового нет (ПЛ-02); долг больше бюджета — новое сокращается (ПЛ-09); выучено после одного чистого «Проверяю себя» (ЗН-02); сессия на 2,5 отрывка даёт две попытки (ПЛ-12).
- Тесты переходов очередей, таблицы оценок, перерыва и диагностики.
- Моделирование: виртуальный человек занимается 90 дней с пропусками (детерминированный `Random`) — план всегда выполним, долг не растёт без предела, сроки не уходят в прошлое.
- Формат, анализатор, тесты, `check_deps` — зелёные; новая зависимость (`fsrs`) — с лицензией и обоснованием в описании PR.

## Не делать

- Не импортировать Flutter и не обращаться к базе: только чистые функции.
- Не менять `contracts`. Если общим пакетам понадобятся типы планировщика — черновик ADR в описании PR.
- Не придумывать числа: всё из параметров ТЗ 12.4. Если чего-то в ТЗ нет — значение в параметры и вопрос владельцу в PR.
