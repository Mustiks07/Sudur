# S04 — проверка ошибок v0

- **Агент:** Opus
- **Ветка:** `opus/s04-check`
- **Можно менять:** `packages/check/`, `packages/testing/` (поддельные данные и наборы для проверки)
- **ТЗ:** 2.8 (ПО-01…ПО-13), 10.5, 12.4 (параметры проверки), 14.2 (таблица для `check`), 15.6 (С-04)

## Что сделать

1. Вход: путь выравнивания из `follow` (P06), паузы между словами, события качества сигнала, параметры из `thresholds.json`. Выход: поток `CheckEvent` из `contracts` с переходами состояний.
2. Кандидаты из пути выравнивания по таблице ТЗ 10.5: пропуск, замена, «не удалось проверить» для среднего сходства, лишнее слово, перескок, повтор, запинка.
3. Подтверждение по контексту (`confirmContextWords`), самоисправление в окне (`selfCorrectionMs`, `selfCorrectionWords`), плохой сигнал → `unverified`, конец сессии → недоподтверждённые становятся `unverified`.
4. Переходы состояний — строго по схеме ТЗ 10.5; из `confirmed` в `corrected` нельзя.
5. «Не согласен» → `disputed` (метод для сессии).
6. Строгое поведение: сигнал «ждать слово», пока ошибочное не прочитано или не взята подсказка; через `strictMaxFails` или `strictMaxWaitMs` — предложение подсказки (ТЗ 10.5, ЭЧ-05).
7. В каждом событии — распознанный текст как есть (ПО-13) и версии модели, правил и текста (ПО-11).

## Готово, когда

- Проходят все случаи таблицы `check` из ТЗ 14.2.
- Тесты переходов состояний, включая запрещённые переходы.
- Перебор по суре 78, как в P06: пропуск каждого слова, замена каждого слова, самоисправление в каждом месте — пропуски и замены подтверждаются, исправленные места становятся `corrected`, на чистом чтении нет ни одной подтверждённой ошибки.

## Порядок

Начинать от свежего `main`, когда Астра сольёт P06 (№3). Если №3 ещё не слит — можно начать от `opus/p06-follow` и после слияния сделать `git rebase --onto origin/main`.

## Не делать

- Не менять `follow` и `contracts`. Если нужны изменения — описать в PR, решает Астра.
- Не подставлять ожидаемый текст вместо распознанного.
