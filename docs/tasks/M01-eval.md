# M01 — инструмент оценки качества на записях

- **Агент:** Opus
- **Ветка:** `opus/m01-eval`
- **Можно менять:** `tools/eval/`, `packages/testing/` (синтетические наборы для тестов инструмента)
- **ТЗ:** 5.3 (показатели и пороги КЧ-01…КЧ-09), 5.5, 12.6 (форматы), 14.2, 15.4 (М-01)

## Что сделать

1. Чтение разметки записей `<id>.ann.json` и результатов распознавания `<id>.<model>.asr.jsonl` по форматам ТЗ 12.6. Записи и разметка лежат вне репозитория (папка из параметра командной строки).
2. Прогон `follow` и `check` на компьютере в том же порядке и с теми же параметрами, что на телефоне; результат одинаков при каждом запуске.
3. Показатели ТЗ 5.3: открыто на своём месте (КЧ-01), лишние открытия (КЧ-02), точность подтверждённых ошибок (КЧ-03), полнота пропусков и замен отдельно (КЧ-04), ложные тревоги на 1000 правильно прочитанных слов (КЧ-05), доля «не удалось проверить» (КЧ-06), самоисправления (КЧ-07).
4. Разбивка по группам: родной язык, пол, класс телефона, шум (КЧ-08). Доверительные интервалы — бутстреп **по людям**, а не по словам (КЧ-09).
5. Отчёт в Markdown и JSON; сравнение с прошлым отчётом в процентных пунктах; итог «прошло / не прошло» и режим выпуска А–Г (ТЗ 5.3).
6. Режим для CI: падает, если точность упала больше чем на 1 п. п. или полнота больше чем на 2 п. п. относительно сохранённого эталонного отчёта (ТЗ 5.5).

## Готово, когда

- Тесты на синтетических наборах, где правильный ответ известен заранее: каждый показатель считается верно, включая краевые случаи (нет ошибок вообще, нет правильных слов).
- Команда из README прогоняет папку с записями и выдаёт отчёт.
- Пока `check` (S04) не слит, показатели проверки ошибок помечены «нет данных», показатели следования уже считаются.

## Порядок

Можно начинать параллельно с S04: сначала показатели следования (КЧ-01, КЧ-02), затем проверки.

## Не делать

- Не коммитить записи, разметку людей и результаты распознавания настоящих записей.
- Не подстраивать пороги в коде: пороги приёмки — из файла параметров.
