# C09 — оценка качества в CI

- **Агент:** Opus
- **Ветка:** `opus/c09-eval-ci`
- **Можно менять:** `tools/eval/`, `packages/testing/`; в `.github/workflows/ci.yml` — один новый шаг для оценки
- **ТЗ:** 5.5 («Набор против ухудшения качества»), 14.2, 15.6 (С-09)

## Зачем

ТЗ требует: изменение `follow`, `check` или `quran_text` не принимается, если точность упала больше чем на 1 процентный пункт или полнота — больше чем на 2. Инструмент оценки (M01) это уже умеет, но в CI не подключён.

## Что сделать

1. **Эталонный набор в репозитории:** только синтетические записи — результаты распознавания, построенные по ключам слов из канона, без звука и без записей людей. Покрыть суру 78 и перескоки по всему Корану: чистое чтение, пропуски, замены, самоисправления, повторы, запинки, перескоки на похожие аяты, неоднозначность.
2. **Сохранённый эталонный отчёт** (JSON) и шаг CI: `tools/eval` в режиме CI сравнивает текущий отчёт с эталонным и падает по правилу ТЗ 5.5.
3. **Осознанное обновление эталона:** команда и описание в README — когда можно обновить эталон (улучшение) и как это оформить в PR, чтобы ухудшение не прошло тихо.
4. **Время шага CI:** не дольше пары минут; если дольше — ограничить набор.

## Готово, когда

- Шаг CI работает на текущем `main` и зелёный.
- Проверено намеренной поломкой: ухудшение порога в ветке роняет шаг (описать в PR, в `main` не сливать).
- Формат, анализатор, тесты — зелёные.

## Не делать

- Не коммитить настоящие записи, разметку людей и результаты распознавания настоящих записей.
- Не менять `follow` и `check` в этой задаче.
