## Зачем

Прототип показал, что основа работает. Для настоящего приложения звук и распознавание должны переживать звонки, уход в фон, смену наушников и отзыв разрешения, хранить фрагменты для разбора только в памяти и выбирать модель по скорости телефона.

## Что сделать

1. **Фрагменты для разбора (ЗВ-02, ЗВ-07):** в памяти — только фрагменты вокруг событий проверки (по 3 с до и после, параметр); удаляются после закрытия разбора; на диск ничего. Тест: 20 минут — фрагменты ≤ 20 МБ памяти.
2. **Прерывания (ЗВ-05):** звонок, смена устройства звука, уход в фон, отзыв разрешения → событие с причиной, сессия на паузе, состояние сохранено. Микрофон Bluetooth-гарнитуры → предупреждение, что проверка может ошибаться.
3. **Разрешение (ЗВ-06):** запрос при первом использовании голоса, понятный отказ → самопроверка. Здесь — сервис и события; текст и экран сделает GPT-A.
4. **Чтец играет — микрофон не слушает (ЗВ-09):** интерфейс «идёт воспроизведение» для сессии; тест «во время воспроизведения нет событий распознавания».
5. **Пакет модели (РС-02, РС-03):** проверка пакета модели по ТЗ 12.3 — без порогов (`thresholds.json`) пакет отвергается; установка — через интерфейс пакетов `content` (Opus делает O05, PR №22; до слияния — работать с интерфейсом и поддельной реализацией).
6. **Тест телефона и выбор модели (РС-04, ТЗ 10.3):** встроенный образец 10 с, правила выбора small / tiny / самопроверка по таблице 10.3, повторная проверка по запросу.
7. **Загрузка модели не блокирует интерфейс (РС-07):** тест на отсутствие блокировок основного изолята.

## Готово, когда

- Тесты каждого пункта на поддельном звуке и распознавателе; формат, анализатор, тесты, `check_deps` — зелёные.
- В PR: «needs owner device check» — какие случаи проверить на Samsung (звонок, наушники, фон, отзыв разрешения).

## Не делать

- Звук и распознанный текст — не на диск и не в журналы (кроме явного сохранения пользователем, ЗВ-07).
- Не трогать `app/` — экраны и тексты делает GPT-A.
- Не менять `contracts` без ADR и согласия владельца.
