# O05 — пакеты содержания и загрузки

- **Агент:** Opus
- **Ветка:** `opus/o05-content`
- **Можно менять:** `packages/content/`, `tools/content_build/` (сборка и подпись манифеста), `packages/testing/` (тестовые пакеты и ключи); `pubspec.lock` — как следствие
- **ТЗ:** 4.9 (ДФ-01…ДФ-07), 11.4, 12.3 (манифест и пакеты), 8.10 (ключи подписи), раздел «Security» в `AGENTS.md`

## Зачем

Модель распознавания, шрифты, разметка, уроки, аудио и переводы приходят на телефон пакетами. Сейчас прототип качает файлы напрямую, по заранее заданным адресам. Нужен надёжный механизм: подписанный манифест, проверка каждого файла, установка «целиком или никак», докачка после обрыва сети, откат на прежнюю версию.

## Что сделать

1. **Манифест** по ТЗ 12.3: модель данных, строгий разбор, проверка подписи Ed25519 по двум встроенным открытым ключам — основному и запасному (ДФ-06). Подменённый или испорченный манифест отвергается. Пакет с `minAppVersion` выше текущей не ставится.
2. **Состояния пакета** строго по ТЗ 11.4: `notInstalled → queued → downloading(%) → verifying → installing → installed`, `failed(причина) → queued`, `installed → updateAvailable`.
3. **Загрузка:** проверка свободного места (размер × 2, ДФ-03), докачка с места обрыва (HTTP Range, ДФ-04), только HTTPS. Сеть и файловая система — через внедрённые интерфейсы, чтобы всё проверялось тестами без сети.
4. **Установка целиком или никак (ДФ-05)** по шагам ТЗ 11.4: временная папка → SHA-256 → безопасная распаковка (запрет путей вне папки, zip-slip) → переименование → смена активной версии одной транзакцией → удаление старой версии после следующего успешного запуска. Запись активной версии — через интерфейс: база пользователя (`storage`, таблица `download`) подключается приложением, сам `content` от `storage` не зависит.
5. **Инструмент в `tools/content_build`:** собрать манифест из готовых пакетов (размер, SHA-256) и подписать его. Закрытый ключ берётся снаружи (файл или переменная окружения) и никогда не попадает в репозиторий. Для тестов — отдельная тестовая пара ключей, помеченная как тестовая.
6. **README:** как выпустить новую версию пакета, где хранится закрытый ключ, что делать при его компрометации (запасной ключ).

## Готово, когда

- Тесты: правильный манифест принимается; подменённый, с чужой подписью и испорченный — отвергаются; обрыв загрузки на середине и докачка; испорченный архив и архив с путём `../` не ломают установленную версию; откат на прежнюю версию; `minAppVersion`; нехватка места.
- Формат, анализатор, тесты, `check_deps` — зелёные; новые зависимости (Ed25519, HTTP, zip) — с лицензией и обоснованием в описании PR.

## Не делать

- Не коммитить настоящие закрытые ключи, модели, шрифты, записи.
- Не трогать `app/` и прототип — подключит GPT-A отдельной задачей.
- Не менять `contracts` без ADR и согласия владельца.
