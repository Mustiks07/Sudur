# O11 — пакет параметров `config`

- **Агент:** Opus
- **Ветка:** `opus/o11-config`
- **Можно менять:** `packages/content/`, `tools/content_build/`, `packages/testing/`; `pubspec.lock` — как следствие
- **ТЗ:** 8.8, 12.3 («Пакет параметров»), 12.4 (все параметры), 4.9, РС-02

## Зачем

Пороги проверки, лимит бесплатной проверки, доли плана, длины пауз должны меняться за день, без выпуска новой версии в магазинах (ТЗ 8.8). Сейчас значения по умолчанию разбросаны по пакетам.

## Что сделать

1. **Схема `config`:** JSON со всеми параметрами ТЗ 12.4, кроме порогов, привязанных к модели (они в пакете модели, РС-02). Разделы по модулям: звук, распознавание (не модельное), план, прочее. Версия схемы.
2. **Встроенные значения по умолчанию** — один файл, созданный строго по таблицам ТЗ 12.4; тест сверяет его с ТЗ (каждый параметр есть, значения совпадают).
3. **Загрузка в `content`:** подписанный файл приходит через манифест (O05), проверяется подпись тем же способом; приложение хранит последнюю проверенную копию; при ошибке — прежняя копия, иначе встроенные значения. Неизвестные поля и значения вне допустимых границ — отвергаются с понятной причиной.
4. **Типизированный доступ:** неизменяемый объект параметров по разделам. Как приложение передаёт разделы в `planner`, `follow`, `check`, `session`, `audio_capture` — описать в README; подключение в `app/` сделает GPT-A.
5. **Инструмент в `tools/content_build`:** собрать и подписать `config` тем же ключом, что манифест.

## Готово, когда

- Тесты: подпись, отказ испорченного файла, откат на прежнюю копию, границы значений, сверка встроенных значений с ТЗ 12.4.
- Формат, анализатор, тесты, `check_deps` — зелёные.

## Не делать

- Не менять пакеты-потребители (`planner`, `follow`, `check`, `session`, `audio_capture`) — только описать подключение.
- Не коммитить закрытые ключи.
