# S05 — сессия чтения v0

- **Агент:** GPT-B
- **Ветки:** `gpt-b/adr-0005-session-contract` (только ADR и `contracts`), затем `gpt-b/s05-session`
- **Можно менять:** `packages/session/`, `packages/audio_capture/` (реализовать новый интерфейс звука), `packages/testing/` (поддельные звук и распознаватель); `packages/contracts/` и `docs/adr/` — только по ADR 0005; `pubspec.lock` — как следствие
- **ТЗ:** 4.3 (потоки), 4.5 (команды и события), 4.6 (как работает проверка в сессии), 10.6 (`session`), 10.3 (имитация потока — уже внутри `asr_sherpa`), 5.2 (НФ-10, НФ-21)

## Зачем

Сессия — сердце экрана чтения: звук → распознавание → следование → проверка → события для экрана. На ней работает прототип P08 (GPT-A собирает экран параллельно, на подставной сессии) и потом настоящий экран «Чтение».

## Что сделать

1. **ADR 0005 — договор сессии (сначала, отдельным PR от свежего `main`).** В `contracts` пока нет команд экрана и части событий ТЗ 4.5. Добавить: команды `StartSession`, `Pause`, `Resume`, `Stop`, `RequestHint`, `DisputeEvent`; события `SessionStarted`, `HintGiven`, `CheckStateChanged`, `SessionFinished` (итог по словам — ТЗ 10.6); интерфейс источника звука для сессии (открыт отрезок, кадры с абсолютным временем, отрезок закрыт, качество сигнала), который реализует `audio_capture`. Поля — строго по ТЗ 4.5. ADR согласует владелец; GPT-A ждёт эти типы для P08, поэтому PR — как можно раньше.
2. **`session` v0** (зависит только от `contracts`, `follow`, `check`, `quran_text` — сервисы ей передаёт приложение через интерфейсы): состояния ТЗ 10.6 `idle → preparing → ready → listening ⇄ paused → finishing → finished` и `error(modelMissing | micDenied | deviceTooSlow)`; звук из интерфейса источника → `SpeechRecognizer.acceptAudio` / `closeSegment`; результаты распознавания → `follow` → `check`; на выходе — поток `SessionEvent`.
3. **Команды экрана:** старт по диапазону и режиму, пауза и продолжение без потери позиции, стоп; подсказки четырёх видов из ТЗ 10.6 (открываемое слово берётся из канона через `quran_text`); «Не согласен» → `disputed`.
4. **`finishing`:** дораспознать открытый отрезок; предварительные события без контекста → `unverified`; `SessionFinished` с итогом для каждого слова диапазона.
5. **Потоки (ТЗ 4.3):** ничего тяжёлее кадра в основном изоляте. Распознаватель и захват звука уже работают в своих изолятах (P04, P05) — описать в README, где что выполняется и почему, и чем это отличается от схемы ТЗ 4.3; если нужно решение — в ADR.
6. **Время событий:** у каждого события `atMs` по одной шкале со звуком, чтобы прототип мог считать задержку появления слова (НФ-10).
7. **`audio_capture`:** реализовать интерфейс источника звука из ADR 0005 (поверх уже сделанных отрезков, кадров и pre-roll).

## Готово, когда

- ADR 0005 написан и слит (с согласия владельца).
- Тесты на поддельном звуке и распознавателе из `packages/testing`: чтение суры 78 открывает все слова по порядку; пропуск → подтверждённая ошибка; пауза и продолжение сохраняют позицию; подсказка каждого вида; `Stop` посреди отрывка → «не прочитано», а не ошибка; нет модели → `error(modelMissing)`.
- Формат, анализатор, тесты, `check_deps` — зелёные.

## Не делать

- Не подставлять ожидаемый текст вместо распознанного (ПО-13); звук и распознанный текст — не в журналы и не на диск.
- Не импортировать `audio_capture` и `asr_sherpa` из `session` — только интерфейсы из `contracts` (правило зависимостей ТЗ 4.2).
- Не трогать `app/` — экран делает GPT-A (P08).
