# M02 — инструмент разметки записей

- **Агент:** GPT-A
- **Ветка:** `gpt-a/m02-annotate`
- **Можно менять:** `tools/annotate/`; в корневом `pubspec.yaml` — только добавить `tools/annotate` в `workspace`; `pubspec.lock` — как следствие
- **ТЗ:** 5.5 (набор записей), 12.6 (формат разметки), 15.4 (М-02)

## Зачем

Владелец записывает свои чтения суры 78 (чисто и с намеренными ошибками) и размечает, где какое слово и какая ошибка. По этой разметке `tools/eval` (M01) считает качество следования и проверки. Цель ТЗ: запись в 1 минуту размечается не дольше 2 минут.

## Что сделать

1. **Страница разметки**, которая открывается двойным щелчком в Chrome на Windows. У владельца не установлены ни Flutter, ни Dart, ни Node, поэтому ничего устанавливать не нужно: один HTML-файл (или папка со статическими файлами), без сети, без CDN, без сборки на стороне владельца.
2. **Выбор папки** с записями (Chrome File System Access API) и файла содержания: `content.json` из `tools/content_build` или готовый `packages/testing/fixtures/content_p582_583.json`. Разметка `<id>.ann.json` сохраняется в ту же папку; если API недоступен — скачивание файла.
3. **Список записей** в папке (wav, m4a, mp3, ogg/opus) с состоянием: нет разметки / черновик / готово.
4. **Сведения о записи:** чтец (`id`, родной язык ru/kk/uz/другой, пол, возраст), условия (класс телефона, тишина/шум), ожидаемый диапазон `from`–`to` по ключам слов.
5. **Слова диапазона** показываются из файла содержания как есть. Инструмент сам не пишет и не меняет арабский текст.
6. **Быстрая разметка:** проигрыватель со скоростью 0,5–1,5×; клавиши: пауза, «конец текущего слова» (ставит `startMs`/`endMs` по порядку), отмена, перемотка на 2 с; статусы слова — по умолчанию `correct`, клавишами `omitted`, `substituted` (с полем «что услышано»), `selfCorrected` (с временем исправления — поле `correction`, как его читает M01), `repeated`, `unclear`; вставка лишнего слова после текущего; перескок.
7. **Подсказка из распознавания:** если рядом лежит `<id>.<model>.asr.jsonl` (12.6), показывать распознанный текст и время токенов как подсказку. Разметку из него не подставлять молча: человек подтверждает каждое слово.
8. **Проверка формата** — команда на Dart `dart run tools/annotate/bin/validate.dart <папка>`: читает каждый `.ann.json` тем же кодом, что `tools/eval` (зависимость по пути, только публичный API), и выводит понятные ошибки. На ней же — тесты в CI.
9. **README для владельца** — по-русски, по шагам, со снимками экрана: как открыть страницу, выбрать папку, разметить запись, какие клавиши.

## Готово, когда

- Владелец размечает запись в 1 минуту не дольше 2 минут (проверить на синтетической записи и описать в PR, сколько ушло).
- Сохранённый файл проходит `validate.dart` и читается `tools/eval` без правок.
- Тесты `validate.dart` на правильных и испорченных файлах; формат, анализатор, тесты — зелёные.
- В PR: снимки экрана и «needs owner check» — что владельцу проверить на своей записи.

## Не делать

- Не отправлять звук и разметку никуда: всё остаётся на компьютере владельца.
- Не коммитить записи, разметку настоящих записей и результаты их распознавания.
- Не писать арабский текст и не менять `tools/eval`. Если формат 12.6 неудобен — описать в PR, решают Opus и Астра.
