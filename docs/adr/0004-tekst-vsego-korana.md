# 0004. Текст всего Корана: хранение и тестовые данные

- Статус: принято
- Дата: 17.11.2026
- Кто принял: владелец (по предложению Opus, задача S03)

## Контекст

Задача S03: следование должно искать место по всему Корану — главная ошибка при заучивании это перескок на похожий аят в другой суре. Сейчас база содержания и тестовые данные знают только страницы 582–583.

- **Текст** всего Корана у нас есть с правами: Tanzil, CC BY 3.0, менять нельзя, нужна ссылка. `content_build` его уже скачивает и проверяет: 114 сур, 6236 аятов, 77 433 слова, контрольная сумма канона.
- **Разметки страниц** с подтверждёнными правами нет (ADR 0002): её берём только для страниц прототипа и только «для прототипа».
- По схеме ТЗ 12.2 у слова обязательны страница, строка, место в строке и знак шрифта. Слово без разметки туда не записать.
- ТЗ 4.9 уже различает пакеты `text` и `layout`.

Замеры на компьютере (текущий код `quran_text`, встроенный нормализатор, весь Коран):

| Что | Результат |
|---|---|
| Текст по аятам (JSON) | 1,55 МБ, в gzip 0,29 МБ |
| Текст по словам, отдельной строкой на слово (JSON) | 6,77 МБ, в gzip 0,81 МБ |
| Предлагаемый формат: по аятам, слова уже разделены | 1,57 МБ, в gzip 0,29 МБ |
| Чтение 77 433 слов из JSON | ≈ 0,2 с |
| Ключи и индекс троек | ≈ 0,34 с (скомпилированный Dart), 0,4 с (JIT) |
| Память процесса после построения | ≈ 70–80 МБ (скомпилированный Dart, с JSON) |
| 1000 поисков по 3 словам | ≈ 2 мс |

Для бюджетного Android ожидаю в 3–5 раз медленнее: 1–2 с на построение. Это не для запуска приложения — значит, строим один раз при установке модели в отдельном изоляте и храним в базе пользователя (`search_key_cache`, `ngram_cache`, ТЗ 12.1). Замер на телефоне — владелец (П-09).

## Решение

Владелец 17.11.2026 согласился со всеми тремя пунктами:

1. текст и разметка хранятся в раздельных таблицах;
2. текст всего Корана (1,57 МБ, Tanzil без изменений, с атрибуцией и проверкой контрольной суммы) коммитится в репозиторий как тестовые данные;
3. схема базы содержания ТЗ 12.2 меняется.

Подробности решения:

### 1. Текст и разметка — раздельно

База содержания хранит текст и разметку в разных таблицах — как пакеты `text` и `layout` в ТЗ 4.9:

| Таблица | Поля | Для каких слов |
|---|---|---|
| `word` | `word_index`, `surah`, `ayah`, `position`, `text_uthmani` | весь Коран |
| `ayah` | `surah`, `ayah`, `first_word_index`, `word_count`, `juz`, `hizb`, `sajda` | весь Коран (`juz`, `hizb`, `sajda` — пока только где есть источник; иначе пусто) |
| `word_layout` | `layout_id`, `word_index`, `page`, `line`, `line_position`, `glyph_code` | только страницы с разметкой |
| `ayah_layout` | `layout_id`, `surah`, `ayah`, `page`, `end_page`, `end_line`, `end_line_position`, `end_glyph_code` | то же |
| `page`, `line` | как сейчас, плюс `layout_id` | то же |

- Пустых полей «страница неизвестна» нет: у слова либо есть строка в `word_layout`, либо нет.
- Разметку можно заменить целиком (например, файлом QUL с правами) или добавить вторую (другой мусхаф) по `layout_id`, не трогая текст.
- Поля `ayah.end_*` и `ayah.page` (приняты в ADR 0002) переезжают в `ayah_layout`.
- `Word` в `quran_text` хранит только текст и место в Коране; страница и строка — у разметки. Сейчас `Word.page` и `Word.line` кроме моих пакетов никто не читает (`mushaf_view` использует свою модель).

### 2. Тестовые данные всего Корана — в репозиторий

В `packages/testing/fixtures/` кладём текст всего Корана **по аятам, уже разделённый на слова** — новый формат JSON (`format: 2`):

```json
{ "format": 2, "contentVersion": { "...": "…, textNotice — уведомление Tanzil дословно" },
  "ayahs": [[78, 1, ["…", "…"]], …] }
```

- Размер 1,57 МБ (в gzip 0,29 МБ) — как сам файл Tanzil. Один аят на строку, чтобы изменения читались в обзоре. Меняется только вместе с каноном: закреплённая контрольная сумма не даст изменить его молча.
- Слова — ровно те куски текста, что режет `content_build`; соединённые пробелом, они дают текст Tanzil байт в байт. `word_index` идёт по порядку, отдельно не хранится.
- Файл собирает `content_build` (флаг `--text-fixture-out`), руками не правится. Тест `content_build` сверяет его контрольную сумму с закреплённой.
- Уведомление Tanzil — внутри файла и в `fixtures/README.md` (CC BY 3.0 разрешает дословные копии с уведомлением и ссылкой).
- Нынешний `content_p582_583.json` остаётся для разметки страниц прототипа.

### 3. Ключи и индекс

`quran_text` строит ключи и индекс троек для всех слов. Интерфейс источника кэша (`search_key_cache`, `ngram_cache` по `normalizer_id`) описываю в `quran_text`; таблицы делает GPT-B в задаче O04.

## Рассмотренные варианты

- **Пустые (`NULL`) страница и строка в `word`.** Проще в коде, но везде появляется «а есть ли разметка», а смена разметки трогает таблицу текста. Отвергнуто в пользу отдельной `word_layout`.
- **Не коммитить текст, скачивать его в CI.** Тесты зависят от сети и сайта Tanzil, CI падает без причины в коде. Отвергнуто.
- **Коммитить по слову в строке (6,8 МБ) или сжатый файл.** Первый вчетверо больше без пользы; сжатый не читается в обзоре изменений. Отвергнуто.
- **Только несколько сур для тестов.** Не проверить «поиск по всему Корану» и перескок в далёкую суру; набор сур пришлось бы выбирать вручную. Отвергнуто.

## Последствия

- Схема 12.2 меняется (таблицы `word_layout`, `ayah_layout`, `layout_id`) — внесено в ТЗ 12.2 этим же изменением. Описание базы содержания в ТЗ 4.8 приведено в соответствие (по проверке Астры 18.11): у `word` нет страницы и строки, разметка может покрывать только часть текста, правила `passage_default`, связанные со страницей, — только в покрытой области. Формат JSON тестовых данных — версия 2.
- `quran_text`: `Word` без страницы и строки, загрузка формата 2, источник кэша.
- `content_build`: собирает текст всего Корана, а разметку — только для страниц из конфигурации.
- В репозитории появится файл 1,57 МБ с текстом Корана (с атрибуцией Tanzil).
- Замеры на бюджетном Android — владелец (П-09); если построение дольше 2–3 с, кэш в базе пользователя обязателен с первого запуска.

## Когда пересмотреть

Когда появится разметка всего мусхафа с подтверждёнными правами или если замеры на телефоне покажут, что индекс в памяти не помещается в бюджет.
