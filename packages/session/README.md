# session

Сессия чтения: звук → распознавание → следование → проверка.

- **Владелец:** GPT-B
- **Задача:** S05
- **ТЗ:** 4.3, 4.5, 4.6, 10.6

Правила: [`AGENTS.md`](../../AGENTS.md). Публичный интерфейс — только `lib/session.dart`; внутренности — в `lib/src/`.

## Публичный API

`ReadingSession` получает через конструктор только договоры и доменные
зависимости: `SessionAudioSource`, `SpeechRecognizer`, `QuranText`,
нормализатор, версии и параметры `follow`/`check`. Команды экрана передаются в
`execute(SessionCommand)`, события читаются из `events`, состояния — из
`states` и синхронного `state`.

Состояния идут по ТЗ 10.6:

```text
idle → preparing → ready → listening ⇄ paused → finishing → finished
                     ↘ error(modelMissing | micDenied | deviceTooSlow)
```

При `Stop` источник сначала отдаёт хвостовые кадры и закрытия. Затем сессия
ждёт окончательные `RecognitionResult` всех закрытых отрезков, завершает
`follow` и переводит оставшиеся предварительные ошибки в `unverified`.
`SessionFinished` содержит ровно один итог каждого слова диапазона. Слова после
места остановки получают `notRead`, а не `error`.

В строгом режиме `strictSignals` передаёт экрану `WaitForWord`, `OfferHint` и
`StopWaiting`. После `WaitForWord` сессия удерживает новые открытия слов до
прочтения ожидаемого слова или подсказки. Периодический `tick` продолжает
проверять предел ожидания даже при отсутствии новых результатов распознавания.

`SessionCheckpointStore`, если передан, получает состояние каждые 30 секунд,
при паузе и завершении. В checkpoint нет звука и распознанного текста.

## Потоки выполнения

Для приложения публичной точкой входа служит `ReadingSessionIsolate`. Она
создаёт `ReadingSession` и все её зависимости через top-level/static factory
внутри долгоживущего изолята. Команды имеют request id и явный `Result`, а
события, состояния, строгие сигналы и безопасные ошибки возвращаются отдельными
потоками. При `dispose` worker освобождает сервисы, после чего закрываются все
порты. Конфигурация factory должна быть isolate-sendable.

Внутри session worker остаются два специализированных долгоживущих worker:

- `audio_capture` принимает PCM от `record`, переносит буферы через
  `TransferableTypedData`, держит VAD, кольцевой буфер и качество сигнала в
  своём изоляте;
- `asr_sherpa` держит sherpa-onnx и декодирование в своём изоляте;
- `ReadingSession` пересылает один кадр через интерфейс, а после результата
  выполняет ограниченное по окну следование и проверку над текстовыми ключами.

Таким образом, оркестрация, PCM, VAD и FFI не выполняются в UI-изоляте, а звук
не копится в `session`. На телефоне всё равно нужна проверка НФ-10 и плавности
интерфейса.

## Конфиденциальность

Аудиокадр сразу передаётся `SpeechRecognizer.acceptAudio`; пакет его не пишет
на диск и не журналирует. Распознанный текст остаётся тем, что вернула модель,
и никогда не заменяется ожидаемым каноническим текстом.
