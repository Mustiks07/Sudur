# storage

Пользовательская база Sudur на drift/SQLite. Схема v1 соответствует ТЗ 12.1:
17 таблиц и 5 обязательных индексов, время хранится в миллисекундах UTC,
идентификаторы принимаются только в формате UUID v4. `outbox` создаётся пустым.

Публичный вход пакета — `lib/storage.dart`. `SudurDatabase.openFile(path)`
получает путь снаружи и открывает SQLite через фоновый исполнитель drift;
`SudurDatabase.memory()` предназначен для тестов. Репозитории возвращают
`Result`, JSON-поля имеют отдельные неизменяемые типы и проверяются как при
чтении из SQLite, так и при импорте.

`DriftAttemptRepository.recordPassage` одной транзакцией пишет попытку,
события проверки и новое состояние единицы плана. Звук в базе не хранится.
`UserDataArchiveService` экспортирует все таблицы в JSON внутри zip и заменяет
данные при импорте только после полной проверки архива. `UserDataEraser`
получает файловую систему через `RecordingFileSystem`, удаляет явно сохранённые
записи и очищает все таблицы.

## Миграции

Эталон v1 лежит в `drift_schemas/drift_schema_v1.json`, сгенерированный
`database.g.dart` коммитится. Для каждой следующей версии нужно:

1. изменить таблицы и увеличить `schemaVersion` ровно на один;
2. добавить явный шаг `onUpgrade` для каждой предыдущей версии;
3. сгенерировать `database.g.dart` и новый снимок командой
   `dart run drift_dev schema dump lib/src/database.dart drift_schemas/`;
4. не менять старые снимки;
5. добавить миграционные тесты с каждого прежнего снимка до текущей версии и
   проверить сохранность данных.

Сейчас workspace удерживает `sqlite3 2.x` через `tools/content_build`, а
совместимый с общим analyzer новый `drift_dev` требует `sqlite3 3.x`. Поэтому
runtime закреплён на drift 2.31, а генерация v1 выполнена в отдельном временном
pub-окружении с `drift_dev 2.31.0` и `build_runner 2.10.4`. После общего
перехода workspace на sqlite3 3.x генератор следует вернуть в
`dev_dependencies` пакета.

## Резервная копия

Настройки платформ находятся в `app/` и не входят в O04. При подключении базы
приложение обязано:

- включить файл базы пользователя в системную резервную копию Android и iOS;
- исключить каталог сохранённых голосовых записей;
- на Android также исключить данные `flutter_secure_storage`, которые нельзя
  расшифровать после восстановления на другом устройстве;
- дать человеку возможность отключить резервное копирование.

## Зависимости

- `drift` 2.31.0 (MIT) — типизированная схема, запросы, транзакции и фоновый
  исполнитель SQLite;
- `archive` 4.0.7 (MIT) — zip для выгрузки и загрузки данных;
- `collection` 1.19.1 (BSD-3-Clause) — сравнение неизменяемых JSON-значений;
- `meta` 1.19.0 (BSD-3-Clause) — аннотации неизменяемости.

## Проверка

```sh
dart format --set-exit-if-changed packages/storage
flutter analyze packages/storage
flutter test packages/storage
bash tools/check_deps.sh
```

На Linux без `libsqlite3.so` тестам нужна системная SQLite. В облачной среде
использовалась ссылка на установленную `libsqlite3.so.0` только в `/tmp` через
`LD_LIBRARY_PATH`; бинарные файлы в репозиторий не добавляются.
