# content

Пакеты содержания: подписанный манифест, загрузка с докачкой, установка «целиком или никак», откат. Сервис на чистом Dart (без Flutter): сеть, файлы, свободное место и база пользователя — через внедрённые интерфейсы, поэтому всё проверяется тестами без сети и без телефона.

- **Владелец:** Opus
- **Задачи:** [O05](../../docs/tasks/O05-content.md), [O11](../../docs/tasks/O11-config.md)
- **ТЗ:** 4.9 (ДФ-01…ДФ-07), 8.8, 8.10, 11.4, 12.3, 12.4; [`AGENTS.md`](../../AGENTS.md), раздел «Security»

Публичный интерфейс — только `lib/content.dart`; внутренности — в `lib/src/`.

## Как пользоваться (приложение)

```dart
final keys = TrustedKeys(main: mainKey, backup: backupKey); // встроены в приложение
final manifest = await verifyManifest(json, keys, notBefore: lastIssuedAt);

final installer = PackageInstaller(
  root: '<папка приложения>/packages',
  appVersion: PackageVersion(1, 0, 0),
  transport: HttpsContentTransport(HttpClient()),
  files: const IoContentFiles(),
  disk: platformDiskSpace,          // свободное место — из платформы
  versions: downloadTable,          // ActiveVersions поверх таблицы `download` (storage)
  extractor: const ZipExtractor(),  // распаковка в отдельном изоляте
);
await installer.install(manifest.package('model-quran-asr-small')!, onState: show);
// после успешного запуска на новых версиях:
await installer.cleanUpAfterLaunch(ids);
```

`content` не зависит от `storage`: приложение реализует `ActiveVersions` поверх таблицы `download` (смена `active_version` — одной транзакцией) и `DiskSpace` поверх платформы.

## Манифест (ТЗ 12.3)

- Подпись Ed25519 по каноническому JSON без поля `signature`: ключи по алфавиту, без пробелов, числа — в записи Dart (кратчайшая, читается обратно в то же значение), NaN и бесконечность запрещены.
- **Подпись проверяется до того, как читается содержимое.** Отвергается: не JSON, нет подписи, неизвестный ключ, подпись не сходится (подменённый манифест или чужой ключ под нашим `keyId`).
- В приложение встроены **два открытых ключа — основной и запасной** (ДФ-06, 8.10). Ключи с `keyId`, начинающимся на `test-`, `TrustedKeys` не принимает (только в тестах, с `allowTestKeys`).
- После проверки подписи — строгая проверка полей: `manifestVersion` (новее поддерживаемого — «unsupportedVersion»), `issuedAt` в UTC, у пакета — `id`, `kind` из списка ТЗ 4.9, версии `x.y.z`, `url` только HTTPS, `size` > 0, `sha256` из 64 шестнадцатеричных цифр, `license`, `minAppVersion`, `dependsOn` — только пакеты этого манифеста, без повторов `id`.
- Неизвестные поля **разрешены**: они тоже под подписью, а новые необязательные поля не ломают старые версии приложения.
- `notBefore` — `issuedAt` последнего принятого манифеста: более старый отвергается (нельзя подсунуть старый подписанный манифест с уязвимым пакетом).

## Состояния пакета (ТЗ 11.4)

```text
notInstalled → queued → downloading(%) → verifying → installing → installed
                                   ↘ failed(причина) → queued (повтор)
installed → updateAvailable → (тот же путь для новой версии)
```

`PackageState.canMoveTo` — разрешённые переходы; `stateFor(пакет, активная версия)` — `notInstalled` / `installed` / `updateAvailable`. Причины `failed`: `appUpdateRequired` («Обновите приложение»), `missingDependency`, `notEnoughSpace`, `insecureUrl`, `network`, `sizeMismatch`, `checksumMismatch`, `badArchive`, `unsafeArchive`, `storage`, `activation`.

## Установка целиком или никак (ДФ-03…ДФ-05)

1. До загрузки: `minAppVersion` ≤ версии приложения, HTTPS, зависимости установлены, свободно не меньше чем «оставшаяся часть архива + размер архива» (не больше размер × 2, ДФ-03).
2. Загрузка в `<root>/<id>/<version>.tmp/package.zip` **с докачкой**: при повторе запрос `Range: bytes=<сколько есть>-`; сервер ответил 206 с тем же началом — дописываем, ответил 200 — начинаем заново. Обрыв — `failed(network)`, загруженное остаётся для следующей попытки. Больше байт, чем в манифесте, — `sizeMismatch`, загрузка удаляется.
3. Проверка размера и SHA-256. Не сошлось — `checksumMismatch`, временная папка удаляется (неверный архив не докачивается).
4. Безопасная распаковка в `<version>.tmp/unpacked/`: сначала проверяются **все** записи, и при одной плохой не пишется ничего — абсолютный путь, `..`, `\`, `:` (буква диска), путь вне папки после нормализации, ссылка (zip-slip). Архив без файлов (мусор, обрезанный файл) — `badArchive`. Распаковка идёт в отдельном изоляте.
5. Активная версия читается из базы **до того, как что-то на диске заменяется**. База не ответила — `failed(activation)`, файлы не трогаются (это могла быть та же версия, что уже работает); проверенный архив остаётся для повтора. Та же версия уже активна — живые файлы не заменяются.
6. Переименование в `<root>/<id>/<version>/`, затем смена активной версии одной транзакцией (`ActiveVersions.activate`). Не удалась — новая папка удаляется, активной остаётся прежняя.
7. После успешной смены установка **успешна**, даже если временную папку удалить не удалось (файл занят и т. п.): уборка отделена от результата и повторяется в `cleanUpAfterLaunch`.
8. Прежняя версия остаётся на диске: `rollBack` возвращает её. После следующего успешного запуска `cleanUpAfterLaunch` удаляет всё, кроме активной, и оставшиеся временные папки активной и старых версий; незаконченные загрузки более новых версий (`.tmp`) остаются для докачки.

Любая ошибка на любом шаге оставляет активную версию и её файлы как были.

## Как выпустить новую версию пакета

1. Собрать архив пакета (zip) — `tools/content_build` для текста и разметки; модель, шрифты и уроки — их собственными инструментами.
2. Добавить или обновить запись в `packages.json` (вид, версия, адрес на CDN, лицензия, `minAppVersion`, `dependsOn`, имя файла).
3. Собрать и подписать манифест **на компьютере владельца** (ключ — вне репозитория):

   ```bash
   dart run tools/content_build/bin/manifest.dart --spec packages.json --files <папка с архивами> --key-id main-2026 --key-file <путь вне репозитория> --out manifest.json
   ```

   Или ключ через переменную окружения `SUDUR_MANIFEST_SIGNING_KEY` (base64 от 32 байт) вместо `--key-file`.
4. Загрузить архивы на CDN по адресам из манифеста, затем — сам `manifest.json`.

## Где хранится закрытый ключ (ТЗ 8.10)

- **Только у владельца**: менеджер паролей + резервная копия вне компьютера. Не в репозитории и не в CI.
- Создать ключ: `dart run tools/content_build/bin/manifest.dart --key-id main-2026 --new-key <путь вне репозитория>` — инструмент пишет файл ключа (только вне репозитория, не перезаписывает существующий) и печатает **открытый** ключ для приложения. Так же создаётся запасной ключ (например, `backup-2026`) — его закрытая часть хранится отдельно от основной.
- Инструмент отказывается подписывать настоящим ключом из файла внутри репозитория и тестовым ключом без `--allow-test-key`.
- Настоящие открытые ключи ещё не созданы: это делает владелец, а открытые ключи встраивает в приложение GPT-A (задача подключения).

## Если закрытый ключ скомпрометирован или потерян

1. Подписывать манифест **запасным** ключом — приложения его уже принимают.
2. Создать новую пару и выпустить версию приложения, где основной ключ — бывший запасной, а запасной — новый; скомпрометированный ключ из приложения убрать.
3. `notBefore` не даёт подсунуть старые манифесты, но манифест, подписанный украденным ключом позже, приложения без нового ключа примут — поэтому шаг 2 срочный.
4. Если потеряны оба ключа, новые пакеты не примет ни одна установленная версия приложения, пока не выйдет обновление с новыми ключами (8.10).

## Пакет параметров `config` (O11; ТЗ 8.8, 12.3, 12.4)

Параметры, которые нужно уметь поправить за день без выпуска в магазинах. Пороги следования и проверки сюда **не входят**: они привязаны к модели и приходят в её пакете (`thresholds.json`, РС-02).

### Файл `config.json`

```json
{
  "configVersion": 1,
  "version": "1.0.0",
  "issuedAt": "2026-11-18T00:00:00Z",
  "audio": { "ringBufferSec": 30, "...": "..." },
  "recognition": { "asrThreads": 2, "...": "..." },
  "plan": { "newShare": 0.2, "diagnosticSize": {"min": 3, "max": 5}, "stepMultipliers": [1.3, 3.0, 8.0], "...": "..." },
  "other": { "freeVoiceMinutesPerDay": 10, "...": "..." },
  "signature": { "keyId": "main-2026", "ed25519": "…" }
}
```

- **Подписан так же, как манифест** (тот же ключ, канонический JSON без `signature`; `verifySignedJson` — общий код). Приходит пакетом вида `config` через манифест; внутри пакета — `config.json`.
- **Строго:** неизвестный раздел или параметр, значение не того вида или вне допустимых границ — файл отвергается с именем значения (`plan.recentLadderDays must be ascending`). Проверяются и правила между значениями: доли плана в сумме 1, `quietDbfs` < `noisyDbfs`, `deviceTestSmallMax` ≤ `deviceTestTinyMax`. Отсутствующий параметр остаётся встроенным.
- `configVersion` новее поддерживаемого — «unsupportedVersion»: прежняя копия остаётся. Добавляя параметр, поднимайте `configVersion` и публикуйте файл для новых версий приложения (старые отвергнут неизвестное поле и останутся на прежней копии).
- Границы значений — защита от испорченного файла, а не настройка; они в `configSchema` рядом со встроенными значениями.

### Встроенные значения

`configSchema` / `AppConfig.defaults` (`lib/src/config_schema.dart`) — строго по таблицам ТЗ 12.4 «Звук», «Распознавание», «План», «Прочее». Тест `config_test.dart` читает эти таблицы прямо из `docs/tz/12-formaty-i-parametry.md` и сверяет каждый параметр и значение: изменение ТЗ без изменения встроенных значений (или наоборот) роняет тест.

### Последняя проверенная копия и откат

`ConfigLoader` (приложение даёт `ConfigStore` — где хранить файл):

- `current()` при запуске — сохранённая копия, проверенная заново; нет её или она испорчена — встроенные значения;
- `accept(json)` после установки пакета `config` — файл проверен и не старше сохранённого → сохраняется и используется; иначе остаются прежние параметры, причина отказа — в `ConfigState.refused`;
- **хранилище может отказать** (`ConfigStore` возвращает `Result`, как все сервисы): не читается — встроенные значения; не записывается — верный файл всё равно используется в этом запуске, а `ConfigState.storeError` говорит приложению, что сохранить не удалось (после перезапуска действует прежняя копия, пока файл не сохранится). Исключения из хранилища загрузчик не пропускает.

### Как приложение передаёт разделы в пакеты

Подключение в `app/` делает GPT-A; пакеты-потребители в этой задаче не менялись.

| Раздел | Кому | Как |
|---|---|---|
| `audio` | `audio_capture` | `AudioCaptureConfig` из `ringBufferSec`, `preRollMs`, `postRollMs`, `segmentEndPauseMs`, `maxSegmentMs`, `quietDbfs`, `noisyDbfs`, `clippingRatio`, `signalHoldMs`; `reviewSnippetPadMs` — экрану разбора ошибки (ЗВ-02) |
| `recognition` | `asr_sherpa` | число потоков, интервал и окно частичных результатов, пороги теста устройства при выборе модели |
| `plan` | `planner` | доли очередей, `hardSpotMaxShare`, `recentDays`, `recentLadderDays`, `desiredRetention`, перерыв и диагностика, скорость чтения, долг, множители шагов, повторы при выучивании; `passageMaxAyahs` — уже учтён в отрывках базы содержания (`content_build`) |
| `other` | `lessons` (`quizPassPercent`, `skillReviewQuestions` → `LessonParams`), `entitlements` (`freeVoiceMinutesPerDay`, `trialDays`, `offlineGraceDays`), отправка записей (`uploadQueueMaxMb`, `uploadWifiOnly`, `opusBitrateKbps`), напоминания, `mushaf_view` (`pageFontWindow`), сам `content` (`manifestCheckHours`), воспроизведение (`listenRepeatPauseFactor`) |

`follow`, `check`, `session` получают пороги из `thresholds.json` пакета модели, не из `config`.

### Как выпустить новый `config`

1. Изменить значения в файле значений (как `packages/testing/fixtures/config/config.values.json`).
2. Подписать (ключ — вне репозитория, как у манифеста):

   ```bash
   dart run tools/content_build/bin/config.dart --values config.values.json --version 1.0.1 --key-id main-2026 --key-file <путь вне репозитория> --out config.json
   ```

3. Упаковать `config.json` в zip, добавить пакет вида `config` в `packages.json` манифеста, подписать манифест, выложить на CDN.

## Тесты

`test/` — на тестовой паре ключей и подписанном инструментом тестовом манифесте из `packages/testing/fixtures/manifest/` (ключи помечены `TEST-ONLY`):

- **манифест:** подписанный инструментом принимается; запасной ключ принимается; изменённый — отвергается; чужой ключ под нашим `keyId` — отвергается; неизвестный ключ, мусор, нет подписи — отвергаются; подписанный, но с ошибками в полях (не HTTPS, неверная версия, вид, зависимость, время, повтор `id`, новая версия формата) — отвергается; неизвестные поля под подписью; старый манифест (`notBefore`); тестовые ключи не принимаются по умолчанию;
- **установка:** тестовый пакет из тестового манифеста ставится; обрыв на середине и докачка с того же байта; сервер без Range; испорченный архив, архив с `../`, не zip — установленная версия цела; лишние байты; `minAppVersion` (без загрузки); нехватка места (граница размер × 2); нет зависимости; база не переключилась; нет сети; откат и очистка после запуска; незаконченная загрузка переживает очистку; база не ответила об активной версии — файлы той же версии и прежней версии не тронуты (замечание Астры к №22); уборка временной папки не удалась — установка всё равно успешна, а папку убирает следующий запуск (замечание Астры к №22); переходы состояний;
- **распаковка:** опасные пути, одна плохая запись — не пишется ничего, не zip и обрезанный архив, распаковка в изоляте;
- **config:** каждый параметр и значение — по таблицам ТЗ 12.4 (тест читает ТЗ; проверено, что изменённое значение роняет тест); пороги модели не входят; подписанный инструментом файл принимается; изменённый — отвергается; значения не того вида и вне границ, неизвестные параметры и разделы, правила между значениями, новый формат — отвергаются с именем значения; отсутствующий параметр — встроенный; загрузчик: встроенные значения без копии, новый файл сохраняется, испорченный — откат на сохранённую копию, после перезапуска — сохранённая копия, более старый файл отвергается, испорченная сохранённая копия — встроенные значения; хранилище не читается или не записывается — без падения (замечание Астры к №24).

## Не сделано

- Фоновая загрузка средствами платформы (WorkManager / URLSession) и проверка манифеста раз в сутки — подключает приложение (GPT-A).
- Защита от «zip-бомбы» (огромный распакованный размер): архив проверен по SHA-256 из подписанного манифеста, то есть это наш собственный файл; предел распакованного размера можно добавить параметром.
