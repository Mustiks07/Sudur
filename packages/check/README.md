# check

Проверка ошибок и их состояния: по пути выравнивания из `follow` решает, где ошибки.

- **Владелец:** Opus
- **Задача:** [S04](../../docs/tasks/S04-check.md)
- **ТЗ:** 2.8 (ПО-01…ПО-13), 10.5, 12.4, 14.2

Правила: [`AGENTS.md`](../../AGENTS.md). Публичный интерфейс — только `lib/check.dart`; внутренности — в `lib/src/`. Чистый Dart, зависит только от `contracts` и `quran_text`.

## Как пользоваться

```dart
final checker = Checker(
  text: quranText, normalizer: normalizer.id,
  from: from, to: to,
  params: CheckParams.defaults,          // или CheckParams.fromJson(thresholds)
  sessionId: id, versions: versions,     // версии модели, правил, текста (ПО-11)
  strict: false,                          // строгое поведение (ЭЧ-05)
);
checker.accept(path: steps, jumps: jumps); // на каждый FollowUpdate
checker.onPause(pause);                    // паузы VAD → запинки
checker.markUnreliable(span);              // плохой сигнал, deviceTooSlow
checker.tick(nowMs);                       // время без слов (окна, строгий режим)
checker.onHint(word, nowMs);               // взята подсказка
checker.dispute(eventId, nowMs);           // «Не согласен» → disputed
checker.finish(endMs);                     // конец сессии
```

Каждый вызов возвращает `CheckUpdate`: новые события и смены состояний (`CheckOutput` = `CheckEvent` из `contracts` + версии) и сигналы строгого поведения (`WaitForWord`, `OfferHint`, `StopWaiting`). Смена состояния — новое `CheckEvent` с тем же `eventId`.

**Вход — свои типы** (`PathStep`, `PathWord`, `JumpInput`): по правилам зависимостей `check` не может импортировать `follow`. Сессия копирует в них `AlignmentStep`, `HeardWord`, `JumpCandidate` поле в поле (пример — `test/helpers.dart`). Перенос этих типов в `contracts` — через ADR.

## Правила (ТЗ 10.5)

| Что в пути | Кандидат | Решение |
|---|---|---|
| Пропуск k слов | Пропуск каждого слова | `confirmed` после `confirmContextWords` сильных совпадений (≥ `strongMatch`) подряд и закрытого окна самоисправления |
| Совпадение со сходством < `substitutionMax` | Замена | так же |
| Лишнее слово, а сразу за ним пропуск ожидаемого | Замена этого слова (`follow` так видит совсем непохожее слово) | так же |
| Совпадение 0,60…0,85 | Замена «средняя» | никогда не `confirmed`: после контекста — `unverified` |
| Лишнее слово | Лишнее; если совпадает с соседним ожидаемым — повтор | как пропуск |
| Найдено место вне отрывка, ≥ `jumpMinWords` слов подряд | Перескок | `confirmed` сразу |
| Возврат назад | Повтор — сигнал, не ошибка | — |
| Пауза внутри аята > `hesitationPauseMs` и > `hesitationTempoFactor` × личной медианы | Запинка — сигнал | — |

- **Самоисправление:** пока окно открыто (не прошло `selfCorrectionWords` слов **и** `selfCorrectionMs`), сильное совпадение с тем же словом переводит кандидата в `corrected`. Поэтому ошибка подтверждается только после закрытия окна. Особый случай: человек пропустил слово, сказал следующее и сразу вернулся — `follow` видит «лишнее слово, равное следующему», и `check` записывает это как пропуск → `corrected`.
- **Плохой сигнал:** кандидат, попавший в `UnreliableSpan`, становится `unverified`, а не `confirmed`.
- **Конец сессии:** все недоподтверждённые → `unverified`.
- **Состояния** — строго по схеме: `preliminary → confirmed | corrected | unverified`, `confirmed → disputed`; из `confirmed` в `corrected` нельзя (`canMove`, `allowedTransitions`).
- **Сигналы** (повтор, запинка) выдаются один раз сразу в состоянии `confirmed` — это «замечено», а не ошибка.
- **Строгое поведение:** при подтверждённом пропуске или замене — `WaitForWord`; каждое услышанное слово, кроме нужного, — неудачная попытка; после `strictMaxFails` попыток или `strictMaxWaitMs` — `OfferHint` (один раз); сильное совпадение с нужным словом или подсказка — `StopWaiting`.
- **ПО-13:** `heardText` всегда как распознано; `expectedText` — канон, только для показа.

## Проверено тестами

Все случаи таблицы `check` ТЗ 14.2 на каноне суры 78 (тестовая копия P03; услышанное — ключи канонических слов с пропусками, заменами, искажениями), переходы состояний, включая все запрещённые, запинки, строгий режим. **Переборы по суре 78:** пропуск каждого слова → подтверждённый пропуск именно там и ничего больше; замена каждого слова непохожим → подтверждённая замена; ошибка в каждом месте с немедленным исправлением → `corrected`, без подтверждённых ошибок; чистое чтение — ни одной подтверждённой ошибки. Последние 4 слова суры в переборы не входят: после них не хватает слов для подтверждения, и это по ТЗ даёт `unverified`.
