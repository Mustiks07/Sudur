# follow

Следование: где сейчас читает человек. Не решает, правильно ли прочитано — это `check`.

- **Владелец:** Opus
- **Задача:** [P06](../../docs/tasks/P06-follow.md)
- **ТЗ:** 2.7 (СЛ-01…СЛ-08), 10.4, 12.4, 14.2

Правила: [`AGENTS.md`](../../AGENTS.md). Публичный интерфейс — только `lib/follow.dart`; внутренности — в `lib/src/`. Чистый Dart, без Flutter.

## Как пользоваться

```dart
final follower = Follower(
  text: quranText,              // QuranText с ключами для normalizer (P02)
  normalizer: normalizer,       // из пакета модели или Normalizer.builtIn
  from: WordKey(78, 1, 1),
  to: WordKey(78, 40, 15),
  params: FollowParams.defaults, // или FollowParams.fromJson(thresholds)
);
final update = follower.accept(recognitionResult); // на каждый результат
final last = follower.finish(sessionId: id, atMs: t); // в конце сессии
```

`FollowUpdate` содержит:

- `events` — `PositionUpdate`, `WordRevealed`, `PositionLost` (контракты ТЗ 4.5);
- `path` — шаги пути выравнивания (`AlignmentStep` из `contracts`, ADR 0003), ставшие окончательными (вход для `check`): `match`, `skip` (со списком пропущенных слов), `back`, `insert`, `unaligned`. В каждом шаге — услышанное слово **как распознано** (ПО-13), ожидаемое слово, сходство, стоимость;
- `jumps` — кандидаты перескока в другое место Корана (СЛ-04); слова там не открываются.

`bind(stream)` делает то же для потока результатов. Работает на сохранённых результатах, без телефона (СЛ-07).

## Как работает

1. **Устойчивая часть (СЛ-08).** Слово частичного результата устойчиво, когда на нём сошлись последние `stableConfirmations` частичных результатов отрезка; все слова окончательного результата устойчивы. Каждое устойчивое слово берётся один раз. Если частичные результаты длинного отрезка покрывают только его конец (ТЗ 10.3), они сшиваются по перекрытию с уже взятыми словами.
2. **Луч (ТЗ 10.4).** До `beamSize` гипотез: позиция, стоимость, история. Переходы — совпадение, пропуск до `maxSkip`, возврат до `maxBack`, лишнее слово; стоимости и пороги — только из `FollowParams`. Гипотезы с одной позицией сливаются (остаётся дешёвая); при равной стоимости первой считается продвинувшаяся дальше.
3. **Окончательные шаги и открытие слов.** Шаг становится окончательным, когда он одинаков у всех гипотез луча, или когда после него услышано ещё `openDelayWords` устойчивых слов и место не неоднозначно. Гипотезы, несогласные с окончательным шагом, отбрасываются — поэтому открытое слово никогда не «отменяется». Слово открывается из окончательного совпадения со сходством ≥ `openThreshold`.
4. **Конец отрезка.** Окончательной становится только уверенная часть пути — подряд идущие прямые совпадения со сходством ≥ `openThreshold`. Пропуск и возврат в конце отрезка ждут следующих слов: «пропустил слово» и «повторил похожее слово» до них неотличимы. `finish()` в конце сессии делает окончательным весь лучший путь.
5. **Потеря позиции.** Если средняя стоимость последних `lostWindowWords` шагов лучшей гипотезы больше `lostCostThreshold` — `PositionLost` (один раз на каждую потерю; `lastConfidentWord: null`, если позиция ещё ни разу не была найдена) и поиск по последним `ngramSize` услышанным словам — **и в отрывке, и по всему Корану** (`QuranText.findSimilar`: каждое слово похоже не меньше чем на `simFloor`, средняя стоимость ≤ `lostCostThreshold`, буквы могут быть расслышаны неверно):
   - **отрывок первым** (ТЗ 10.4): если место в отрывке есть и место вне отрывка не лучше его заметно — привязка к отрывку; несколько мест в отрывке держит луч как неоднозначность (СЛ-05);
   - место вне отрывка **лучше на `ambiguityMargin` и больше** — кандидат перескока для `check`, слова там не открываются. Это главная ошибка при заучивании: похожий аят в другой суре;
   - несколько мест вне отрывка почти одинаково хороши — перескок не объявляется, пока слово их не различит;
   - `matchedNgrams` кандидата — тройки, где каждое слово совпало со сходством ≥ `openThreshold`.
   Слова, долго не нашедшие места, отдаются в путь как `unaligned`.
6. **Неоднозначность (СЛ-05).** Если в луче есть гипотеза в другом месте отрывка (дальше `maxSkip` слов от лучшей) со стоимостью ближе `ambiguityMargin`, отправляется `PositionUpdate` с `confidence: low` и кандидатами, а шаги не становятся окончательными до различающего слова.

## Весь Коран (S03)

Тесты `test/whole_quran_test.dart` работают на тексте всего Корана (`packages/testing/fixtures/quran_text.json`, ADR 0004): перескок в далёкую суру; перескок с неверно расслышанными буквами; похожий аят в другой суре — кандидат перескока, а не открытие слов отрывка; повторяющийся аят суры 55 — неоднозначность без ложного открытия, следующий аят её снимает; чтение не из Корана ничего не находит; чистое чтение суры 78 — как раньше.

**Цена.** Поиск при потере позиции — один `findSimilar` на услышанное слово, пока позиция не найдена: ≈ 20 мс на компьютере, ≈ 60–100 мс на бюджетном Android (оценка; замеры `quran_text` — в его README). Пока позиция есть, поиск по Корану не идёт. Память — текст и индексы всего Корана (≈ 80 МБ процесса на компьютере).

## Проверено тестами

Случаи ТЗ 14.2 на каноне суры 78 (тестовая копия из P03; услышанные слова — ключи канонических слов с пропусками, повторами и искажениями букв): чистое чтение, начало с 5-го аята, повтор 3 слов, пропуск слова, переход на другую суру, меняющиеся частичные результаты, длинная пауза, сшивание скользящих окон. Неоднозначность — на синтетическом отрывке из латинских заглушек (в суре 78 нет повторяющихся троек слов). Переборы по всей суре: начало с каждого аята, пропуск каждого слова, повтор трёх слов в каждом месте, потеря буквы в каждом слове.

## Известные ограничения v0

- Совсем непохожее слово вместо ожидаемого (сходство < `simFloor`) по модели стоимостей ТЗ стоит «лишнее + пропуск» = 2,0; при `costBack` = 0,3 возврат к случайно похожему слову бывает дешевле. Тесты проходят, но пороги нужно калибровать на записях (М-04).
- Начало чтения не с начала отрывка: слова открываются после `ngramSize` услышанных слов.
- **Холодный старт на похожем начале.** Если чтение с самого начала похоже на начало отрывка, но это другое место, следование принимает его за начало отрывка с плохим распознаванием: ничего не открывает (сходство ниже `openThreshold`), но и перескок не объявляет. Перескок ловится, когда человек читал отрывок и ушёл в похожее место.
- Нечёткий поиск требует, чтобы искомые слова стояли подряд; пропуск или лишнее слово внутри окна из `ngramSize` слов он не прощает.
- Паузы (события VAD) в v0 не используются: позиция и так сохраняется при паузе любой длины.
