# audio_capture

Микрофон, кольцевой буфер, Silero VAD и качество сигнала. Основной изолят
только управляет пакетом `record` и без обработки пересылает PCM16 через
`TransferableTypedData`; Float32, VAD, сегменты и качество работают в
долгоживущем worker-изоляте. Звук хранится только в кольцевом буфере памяти.

- **Владелец:** GPT-B
- **Задача:** [P05](../../docs/tasks/P05-audio-capture.md)
- **ТЗ:** 2.5, 10.2

Правила: [`AGENTS.md`](../../AGENTS.md). Публичный интерфейс — только `lib/audio_capture.dart`; внутренности — в `lib/src/`.

## Silero VAD

```sh
packages/audio_capture/tool/download_silero_vad.sh
```

Скрипт скачивает `silero_vad.onnx` из официального релиза sherpa-onnx,
проверяет закреплённый SHA-256 и сохраняет модель с лицензией MIT только в
игнорируемом `third_party_cache/audio_capture/`.

## Использование

Перед `startMicrophone` экран обязан показать локализованное объяснение
разрешения и передать `permissionExplanationShown: true`. Отказ возвращается
как `Result.error(code: micDenied)`, чтобы экран предложил самопроверку.
`AudioCaptureService` создаётся с идентификатором текущей сессии.

Пакет предоставляет:

- поток PCM16 16 кГц mono через `record`;
- `SpeechSegmentOpened`, последовательность `SpeechSegmentAudioFrame` с
  абсолютным временем и `SpeechSegmentClosed` для передачи открытого отрезка
  в `SpeechRecognizer` и частичных результатов;
- сегменты с pre/post-roll и длительностью паузы;
- общий `contracts.SignalQuality` с уровнями `ok`, `tooQuiet`, `clipping`,
  `noisy`; для плохого сигнала `sinceMs` указывает начало измеренного отрезка;
- только явные in-memory фрагменты через `requestSnippet`;
- системные паузы через `notifyInterruption` и перезапуск при смене устройства;
- защиту `setPlaybackActive`, при которой микрофон не подаётся в конвейер;
- real-time режим `startFile` для mono PCM16 WAV без записи новых файлов.

Наблюдатель приложения должен передавать уход в фон и смену аудиоустройства;
`record` самостоятельно сообщает автоматическую паузу при аудиопрерывании.
Очистка аудиопамяти при паузе не сбрасывает единую временную шкалу сессии.
Завершённые native-сегменты sherpa VAD извлекаются через `pop()`, поэтому их
очередь не растёт на длинной записи.
После закрытия разбора вызывающий код обязан освободить ссылку на
`AudioSnippet`; пакет копии фрагментов не хранит.

## Зависимости

- `record 6.1.2` (MIT) — кроссплатформенный поток PCM16 и разрешение;
- `sherpa_onnx 2.0.1` (Apache-2.0) — официальный Silero VAD FFI;
- `crypto 3.0.6` (BSD-3-Clause) — проверка SHA-256 VAD до загрузки.

Unit-тесты используют только синтетические массивы в памяти. Интеграционный
тест настоящей модели включается через `SUDUR_SILERO_VAD_PATH`; CI модель не
скачивает.

Нужна проверка владельцем на Android и iOS: первое разрешение и отказ,
20 минут без потерь, звонок, background/foreground, смена проводной и
Bluetooth-гарнитуры, отзыв разрешения и отсутствие событий во время
проигрывания чтеца.
